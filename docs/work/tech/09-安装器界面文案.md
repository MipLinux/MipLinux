## 一、4 条待确认 —— **已于 2026-10-02 全部确认**

> ✅ 维护者裁决：① **覆盖 P12**（常见时区小表 + 冷门回退 `UTC±xx`，名字改动逐次过审）；② 用户名提示**按后端规则**（小写字母开头）；③ 密码 6 位**只当界面规则**；④ 「语言」页 = 装后系统 locale，普通模式主机名 = 用户名。以下保留原提问与理由，作为决策记录。

| # | 事项 | 说明 |
|---|---|---|
| **1** | **时区显示名与 `06` 的 P12 冲突** | P12 已定的一条是「**照实显示 IANA id**，我们只呈现、不撰写 —— 显示名一旦由我们撰写，风险就从 tzdata 转到我们身上」。你现在要的 `中国标准时间（UTC+08:00）` 正是**由我们撰写**的显示名，等于选 P12 里列的**方案 B**；而 P12 对方案 B 写明要先回答「**谁来审、按什么标准、多久复核一次**」。请确认要覆盖 P12 的那条，并定这份名表怎么维护（我倾向于：常见时区一张小表 + 冷门回退到 `UTC+08:00` 这种纯数字形式，两语言各一份，改动要过你审核）。 |
| **2** | **用户名提示与后端冲突** | 你批注写「以小写字母或连字符开头」，但后端 `validate_user()` 的规则是「**小写字母开头**，后跟小写字母/数字/下划线/连字符（useradd 的规则）」。以连字符开头的用户名 `useradd` 根本建不出来，所以文案按**后端**写。若你确实要放宽，那要同时改后端与 `useradd` 的可行性。 |
| **3** | **密码「至少 6 位」目前只是界面规则** | 后端**不校验密码长度**（`--password-stdin` 原样交给 `chpasswd`）。也就是说走 CLI 可以设 1 位密码。要么这条只当界面防呆（现状），要么后端也加一道（另开一条工作）。 |
| **4** | **「语言」页的语义 + 普通模式主机名** | 我按「页面的『语言』= 装后系统的 locale（`--locale`，高级专属）；界面语言是顶栏『中 / EN』按钮」来写；普通模式主机名 = 用户名（校验不过回退 `mipl`）。不对就说。 |

「高级安装」开关在**欢迎页**；打开后步骤表即时变长。步骤感用 `LinearProgress` + 「第 N / M 步」。

## 四、i18n 机制（2026-10-04 随 Electron 改定）

- **源语言 = 简体中文**：`renderer/i18n/zh_CN.json` 是唯一源，键就是本表的 ID（`nav.next` → `"下一步"`）；
  `en_US.json` 是同键的英文。页面里**只引用键**，不写裸字面量。默认中文，顶栏「中 / EN」可切。
- **运行时**：渲染层加载两份 JSON；`--lang=zh_CN|en_US` 由启动器透传给 Electron（供测试），
  首帧就得是对的语言（与主题同理）；界面内切换不重启进程，重渲染即可。
- **没有构建步骤**：不再需要 `lupdate` / `lrelease` / `.qm` —— JSON 直接进仓库、直接读。
- **守卫**：`tools/i18n.py --check` 断言「本表 104 条界面文案 + 附 A 34 条时区名 = 138 个键，两份 JSON 都有、且与本表逐字相等」，
  页面与探针用同一份表。文案改动**必须过维护者审核**，PR 里附中英对照 diff。

## 五、换栈之后的落地方式（2026-10-04）

QML 时代的「四条并行线」（i18n 基础设施 / 骨架 + Mock / 普通 8 页 / 高级 4 页）随 QML 实现一并作废 ——
它们的产物已经不在仓库里，只留下可复用的判据与文案。现在的落地方式是一条工作（见工作 issue）：

1. **骨架 + i18n + token**：Electron 外壳、步骤表（8/12 动态）、两档版式、`i18n/*.json`、`design/color.json` → CSS 变量
2. **12 个页面**：普通 8（含欢迎页与擦除确认页）+ 高级 4（语言 / 键盘 / 时区 / 主机名）
3. **离屏验收**：Node 单测 + Electron 探针（渲染、i18n、截图）；真 ISO / `cage` 里的 V3 / V5 / V7 仍算未实测

真后端耦合层与逐屏接线留到后面那条线。
