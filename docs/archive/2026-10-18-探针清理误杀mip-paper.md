# 2026-10-18 · 探针清理泛匹配误杀 mip-paper：Chromium GPU FATAL 与 core dump

> 阶段：安装器前端离屏探针测试与残留清理流程。  
> 症状：会话中临时执行 `pkill -f "electron43/electron"` 误杀宿主机运行中的 `mip-paper.service`（KDE 动态壁纸），导致 Chromium 触发 GPU FATAL 并产生 26.6 MB 的 core dump。  
> 根因一句话：`pkill -f` 按完整命令行泛匹配命中同机所有 Electron 进程及其子进程；探针未配置独立的 `--user-data-dir` 缺乏唯一特征；主进程在优雅关闭窗口内因子进程全灭被 Chromium 判为不可恢复崩溃（`LOG(FATAL)` 触发 `SIGTRAP`）。  

---

## 一、时间线与证据链

2026-10-18 21:39:47，为清理探针残留实例，会话中临时执行了 `pkill -f "electron43/electron"`。

约 60 ms 内，宿主机 `mip-paper` 的 journal 记录如下：

```
21:39:47.448986 bash -c "pgrep -af \"electron43/electron\" ...; pkill -f \"electron43/electron\"; ..."
21:39:47.509313 Network service crashed or was terminated, restarting service.
21:39:47.512620 Failed to send GetTerminationStatus message to zygote (×2)
21:39:47.514255 GPU process launch failed: error_code=1002 (×6，1 ms 内)
21:39:47.515232 FATAL:content/browser/gpu/gpu_data_manager_impl_private.cc:416] GPU process isn't usable. Goodbye.
21:39:48.476075 mip-paper.service: Main process exited, code=dumped, status=5/TRAP
21:39:51.478629 mip-paper.service: Started Mip-Paper.
```

## 二、根因分析

1. **泛匹配误伤同机应用**：`-f` 按完整命令行匹配，命中了 `/usr/lib/electron43/electron /usr/lib/mip-paper` 主进程、zygote、network service、GPU 进程，乃至执行该命令的 shell 进程自身。
2. **探针缺乏独立特征**：探针未指定 `--user-data-dir`，默认使用用户级目录，无法与宿主机其它 Electron 应用做正交区分。
3. **Chromium 级联崩溃机制**：
   - 主进程收到 SIGTERM 后未立即退出（执行异步 cleanup await），但网络、zygote、GPU 子进程已被强杀；
   - Chromium 在这段关闭窗口内把 GPU 子进程消失当做异常崩溃并尝试重拉；
   - 因 zygote 亦被杀，6 次启动全败，fallback 耗尽后 Chromium 调用 `IntentionallyCrashBrowserForUnusableGpuProcess()` → `LOG(FATAL)` → 执行 `int3; ud2`（触发 `SIGTRAP` 产生 core dump）。

## 三、排错方法

1. `coredumpctl info <pid>` 查阅崩溃信息：发现退出信号为 `Signal: 5 (TRAP)`，栈顶反汇编为断点指令 `int3; ud2`，并非野指针或内存越界。
2. 解压 core 文件使用 `strings` 检索日志：精准提取到 `GPU process isn't usable. Goodbye.`，证实为 Chromium 主动 crash。
3. 对齐 systemd journal：将 `pkill` 执行点（.448）、网络/zygote 退出（.509/.512）、GPU 重试耗尽（.514）与 FATAL 崩溃（.515）钉死在同一事件链上。

## 四、修法与防范

1. **规约层限制（根 [`AGENTS.md`](../../AGENTS.md)）**：
   - 将 `pkill` / `kill` / `killall` 明确列入「破坏性命令先问后做」清单。
   - 严禁用 `electron` 等宽泛词泛匹配，探针清理必须精准匹配唯一目录路径、脚本路径或明确 PID。
2. **探针进程隔离与生命周期管理（[`probe-render.js`](../../installer/frontend/app/tools/probe-render.js)）**：
   - 显式传递 `--user-data-dir=/tmp/mipl-probe-data`，Chromium 全链条所有子进程自动继承该参数作为唯一特征。
   - 保存子进程 PID 至 `/tmp/mipl-probe.pid`，退出时清理；父进程捕获 `SIGINT`/`SIGTERM` 向子进程转发。
   - 提供 `node tools/probe-render.js --clean`，只排查包含该唯一特征或 PID 的进程，启动探针前自动收敛，彻底杜绝手动执行 `pkill -f electron*`。
3. **文档指引（[`installer/frontend/app/README.md`](../../installer/frontend/app/README.md)）**：
   - 明确列出安全的清理命令，并标明严禁泛匹配 `electron` 的警告。
