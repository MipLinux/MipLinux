# 技术细节 01 · 容器环境搭建

> 目标：**知道构建容器怎么用、坏了怎么查**。建环境本身不需要你动手 —— `sudo ./scripts/mipl.sh build`
> 一条命令就把 bootstrap 取回来、校验、解压、装好工具链；本文只讲怎么确认它好着、以及各步骤失败时怎么定位。
>
> 产物：`/var/lib/machines/archbuild`，由 systemd 当作 `archbuild.scope` 管理。

---

## 前置条件

宿主机需要：

| 项 | 要求 | 检查命令 |
|---|---|---|
| `systemd-nspawn` | 随 systemd 提供 | `command -v systemd-nspawn` |
| 磁盘空间 | ≥ 20 GB 空闲 | `df -h /var/lib/machines` |
| 网络 | 能访问镜像站 | — |

**不需要**在宿主机安装 `archiso`、`pacstrap`、`mkarchiso`——这些都在容器里。

## 步骤 1 · 建环境

```bash
sudo ./scripts/mipl.sh build     # 首次会顺带建好环境，然后开始构建
```

**建环境没有手工步骤**，也不必知道脚本内部走了哪几步 —— 那些步骤属于脚本，写在这里会漂。
这一节只留**失败时怎么定位**：

- **`pacman` 静默失败、装不上包** → 容器里的源与 DNS 不对。bootstrap 自带的 `mirrorlist` 只有寥寥几行有效内容、
  `resolv.conf` 解析不了，脚本会换成宿主机生成的两份（容器里的原文件不动）。要换源或换 DNS：
  `MIPL_DNS="1.1.1.1 8.8.8.8" sudo ./scripts/mipl.sh build`。
- **`bootstrap` 一行报「未下载 / 校验不过」** → 缓存坏了或没下完。脚本会比对 sha256 清单与 zstd 完整性，
  坏了直接删掉重下；手动清缓存：`sudo ./scripts/mipl.sh clean --bootstrap`。
- **nspawn 报找不到 init 或 `os-release`** → 上次解压没完成。脚本判的是「**能不能用**」（能执行的 shell /
  动态链接器 / `pacman`），不是「文件在不在」—— 半途而废的解压恰好能骗过后者（Issue #32）。
- **容器里 `archiso` 装完仍没有 `mkinitcpio`** → `archiso` 不依赖 `mkinitcpio`，必须显式装。
- **`--bind` 报目标路径已存在** → 上次没干净退出，见下面「容器生命周期」。
- **想看脚本到底做了什么** → `sudo ./scripts/mipl.sh -n build`，原样打印且不做改动。

**验证环境好没好：**

```bash
sudo ./scripts/mipl.sh doctor      # 逐项探测；toolchain 那一行会点名缺的是哪几个包
```

### ⚠️ 不要给 nspawn 加 `-b`（历史坑，脚本已规避）

bootstrap 的 `/etc/shadow` 里 root 是 `root:*:...`，`*` 表示没有有效密码 —— 加了 `-b` 会停在
`archbuild login:` 且任何输入都不被接受。构建也不需要容器内有 init 在跑：`mkarchiso` 是普通脚本。
这条记在这里是因为不少人第一次手工搭环境都栽在它上面。

## 步骤 2 · 退出与再次进入

> **这一节很重要。** 容器不会因为你关闭终端而停止，错误的退出方式会留下残留状态，导致下次无法进入。详见[容器生命周期](#容器生命周期必须理解的一节)。

### 退出（推荐方式）

```bash
# 在容器内
poweroff
```

或者退出 shell 后，在宿主机干净关掉：

```bash
sudo machinectl poweroff archbuild
```

### 再次进入（后续日常使用）

```bash
sudo ./scripts/mipl.sh shell      # 进容器；容器不在时它会让你先跑 build
sudo ./scripts/mipl.sh stop       # 关容器
```

**不要手抄 nspawn 命令。** 挂载点由脚本从仓库自身位置推导（Issue #7 就是文档写死了某台机器的家目录），
`profile/` 会只读挂到 `/profile`、`out/` 挂到 `/out` —— 手抄一份就会漏掉或写错其中一项。
容器不存在时 `shell` 会直接报错让你先 `build`，不会给你一个半成品环境。

**不需要重复建环境**——容器状态是持久的。

## 容器生命周期（必须理解的一节）

### 终端 ≠ 容器

这是最容易误解的一点：

| | 是什么 | 关闭它会怎样 |
|---|---|---|
| **终端 / 会话** | 接到容器控制台的一个连接 | 只是断开连接，**容器继续运行** |
| **容器** | systemd 管理的一个 machine（`archbuild.scope`） | 需要显式 `poweroff` / `terminate` 才会停止 |

**容器是「启动了就一直在」的东西。** 直接关掉终端窗口，容器不会消失——它会继续运行并**继续占用 `archbuild` 这个机器名**。

### 机器名的占用规则

`systemd-nspawn` **用 `-D` 目录的 basename 作为机器名**（`-D .../archbuild` → 机器名 `archbuild`）。这个名字用于：

- `/run/systemd/nspawn/<机器名>/` 下的运行时目录
- `/run/systemd/machines/<机器名>` 的注册
- `archbuild.scope` 这个 unit

**同一时刻只能有一个叫 `archbuild` 的容器。** 上一个没退出，下一个就进不来，报：

```
Mount point '/run/systemd/nspawn/archbuild/unix-export' exists already, refusing.
```

**这个报错信息具有误导性**——它说的是挂载点冲突，真实原因是机器名被占用。看到它时，第一反应应该是「是不是还有个容器在跑」，而不是去查挂载点。

### 检查容器的实际状态

```bash
machinectl list                    # 有没有在跑的容器
machinectl status archbuild        # 详情：启动时间、Leader PID、内部服务
```

`machinectl status` 会显示 `Since:`（启动时间）和 `Leader:`（容器内 systemd 的 PID）。**如果这两项存在且进程还活着，容器就在运行。**

### 终端已经关掉了怎么办

**不要紧，容器不依赖那个终端。** 两条路：

#### 方案 1 · 收掉重开（最简单）

```bash
sudo machinectl poweroff archbuild     # 干净关机（容器里是 systemd，这个能用）
# 或
sudo machinectl terminate archbuild    # 强杀，不留清理时间

machinectl list                        # 确认列表为空
```

两个命令的区别（`man machinectl`）：

| 命令 | 行为 |
|---|---|
| `poweroff` | 向容器 init 发 `SIGRTMIN+4`，**走正常关机流程** |
| `terminate` | **立即杀死**所有进程并释放资源，不做清理 |

然后按正常方式重新进入即可。**代价是容器内未保存的状态会丢失**——如果里面没有正在跑的长任务，直接 `terminate` 最省事。

#### 方案 2 · 钻进正在跑的容器（不重启）

`machinectl login` 会**新开一个终端**接到容器的控制台，不需要重启容器：

```bash
sudo machinectl login archbuild
```

进去后可以顺手修掉那个「无法登录」的根因：

```bash
passwd            # 给 root 设密码 ← 设完以后用 -b 也能正常登录
exit
```

> 若 `machinectl login` 不可用，还可用底层手段 `nsenter`：
> ```bash
> machinectl status archbuild | grep Leader      # 取 Leader PID
> sudo nsenter -t <PID> -a
> ```
> `machinectl` 内部做的也是同一件事。

### ⚠️ 不要用 `Ctrl+]` 三次

在宿主机按 `Ctrl+]` 三次会强杀容器，**可能留下残留状态**（运行时目录、machine 注册、scope unit 没被清理），下次进入就会遇到机器名冲突。

**这是产生本文档所述故障的典型路径。** 请用 `poweroff`。

### 需要并行开多个会话时

用 `--machine=` 给每次调用不同的名字，避免撞名：

脚本自己能用 `--restart` 关掉旧容器再进：

```bash
sudo ./scripts/mipl.sh shell --restart
```

真要并行两个会话（少见），才需要给每次调用不同的机器名 —— 但**别照抄别人机器上的 `--bind` 路径**：
挂载点该写什么由脚本推导（`out/` 在容器里固定是 `/out`），路径写死正是 Issue #7 的成因。
正常流程下一次只用一个会话，干净退出就够了。

### 一句话规则

> **每次用完，在容器内 `poweroff`，或在宿主机 `machinectl poweroff <名字>`。**
> **不要关窗口，不要按 `Ctrl+]`。**

## 验证清单

一条命令给全部答案：

```bash
sudo ./scripts/mipl.sh doctor
```

**判据是它的结论行，不是「某一行为 ✅」** —— 检查项由脚本按当前实现给出，缺哪个会点名并附上补齐命令
（本文不复述那份清单，免得与脚本漂开）。只有一条要自己看：`toolchain` 里 **`mkinitcpio` 是单独列的**，

## 常见问题

### 报 `Mount point '.../unix-export' exists already, refusing.`

**真实原因不是挂载点，而是机器名 `archbuild` 已被占用**——多半是上一次的容器还在运行（常见于直接关掉了终端窗口）。

```bash
machinectl list                    # 看有没有在跑的容器
machinectl status archbuild        # 看 Since / Leader

sudo machinectl poweroff archbuild # 收掉旧的
machinectl list                    # 确认为空
```

然后重新进入即可。详见[容器生命周期](#容器生命周期必须理解的一节)。

### 停在 `archbuild login:`，输入任何密码都进不去

**原因：命令里带了 `-b`。**

bootstrap 的 `/etc/shadow` 中 root 是 `root:*:...`，`*` 表示没有有效密码，所以登录必然失败。

**解决：去掉 `-b`，改为 `-u root`。**

```bash
sudo systemd-nspawn -D /var/lib/machines/archbuild -u root
```

详见步骤 1 的说明。**这是本流程最常见的错误，且报错信息具有误导性**——看起来像是密码错了，实际上是没有密码。

> 如果你已经处于这个状态（容器带 `-b` 跑着但登不进去），见[容器生命周期](#容器生命周期必须理解的一节)的「终端已经关掉了怎么办」。

### `-b` 后面跟的脚本没有执行

`-b` 会把命令行参数当作 **init 的参数**，而不是要执行的命令。去掉 `-b` 即可。

### `pacman -S` 报 PGP 签名错误

密钥环没初始化。回到步骤 4.1。

### nspawn 启动报找不到 init 或 os-release

解压时漏了 `--strip-components=1`，文件被埋在 `root.x86_64/` 下。重新解压。

### nspawn 报 execv failed，说 No such file or directory

**这不是权限问题，也不是 nspawn 的毛病 —— 容器里没有能执行的 shell。**

`systemd-nspawn` 不带命令时会按 `/bin/bash` → `/bin/sh` 的顺序找一个能用的
shell；这句报错的意思是这两个（在容器里是同一个 symlink）都执行不了。

**成因**：解压被中断（Ctrl-C、断线、盘满、归档本身是半截的）。
`etc/os-release` 在归档里排第 630 条、`usr/bin/bash` 排第 5815 条，
所以半成品恰好会留下 `os-release`，于是所有「文件在不在」的检查都说 OK。

**先确认：**

```bash
ls /var/lib/machines/archbuild/usr/bin/bash
zstd -t /tmp/archlinux-bootstrap-x86_64.tar.zst     # 半截文件在这里就会报
#   报 `premature end` 就是它 —— 归档本身不完整
```

**重建**（残缺的目录必须删掉，否则下次运行还会把它当成「已初始化」）：

```bash
sudo rm -rf /var/lib/machines/archbuild
sudo rm -f /tmp/archlinux-bootstrap-x86_64.tar.zst*   # 连半截缓存一起清
sudo ./scripts/mipl.sh build
```

**脚本现在已经会自己认出这些情况**（Issue #32）：缓存先过 `sha256` 与 `zstd`
完整性，坏了就删掉重下；解压前后各查一次容器是否真的能用；`mipl doctor` 会直接报
`[!!] container ...（残缺！缺：...）`，而不是一句「已初始化」。要手清缓存：
`sudo ./scripts/mipl.sh clean --bootstrap`。

### 容器里装不上包：`failed to synchronize any databases` / `target not found`

**先分清是哪一头的问题**，症状都是「`archiso` / `mkinitcpio` 装不上」：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `failed to synchronize any databases` | 源不可用：mirrorlist 只剩 `Include` 转发，或那个目录是空的 | 写一份真源（4.2.1），或直接 `sudo ./scripts/mipl.sh build`（它自己挂一份清华源进去） |
| `Could not resolve host` / 卡住不动 | 容器里 DNS 废了：`/etc/resolv.conf` 只有注释 | `cat /etc/resolv.conf` 看有没有 `nameserver`；没有就 `MIPL_DNS="1.1.1.1" ./scripts/mipl.sh build` |
| `invalid or corrupted package (PGP signature)` | 密钥环没初始化 | 容器内 `pacman-key --init && pacman-key --populate archlinux` |
| `signature from "…" is unknown trust` | 同上，或宿主机时间差太多 | 同上，并检查 `date` |

**这两个坑的根源在于 bootstrap 自带的那两份文件：**

```bash
# 容器自带的 mirrorlist：有效内容全是转发，指向的目录可能是空的
grep -v '^#' /var/lib/machines/archbuild/etc/pacman.d/mirrorlist | head
# → Include = /etc/pacman.d/mirrorlist.d/*.conf

# 容器自带的 resolv.conf：纯注释，一个 nameserver 都没有
cat /var/lib/machines/archbuild/etc/resolv.conf
# → # Resolver configuration file.  （下面什么都没有）
```

所以 `mipl build` 不再依赖它们：生成 `<out>/mirrorlist` 与 `<out>/resolv.conf`，
只读挂到容器里，容器内的原文件不动。

### 容器里 `pacman -S archiso` 装完还是没有 `mkinitcpio`

**`archiso` 不依赖 `mkinitcpio`**，只装它永远不会带上。显式装：

```bash
pacman -S --needed archiso mkinitcpio arch-install-scripts
```

`mipl build` 现在装的就是这三个，并在装完后逐个命令验证
（`mkarchiso` / `mkinitcpio` / `mksquashfs` / `xorriso` / `mkfs.vfat` …），
缺任何一个都会点名报出来，而不是等 `mkarchiso` 跑到一半才失败。

### 解压时大量 `无法创建符号连接：权限不够`

`tar` 命令没有用 `sudo`。bootstrap 中包含需要 root 权限的符号链接与 capabilities。

**注意：这类错误不会让 `tar` 返回非零退出码**，容易误以为解压成功。解压后务必检查：

```bash
sudo ls /var/lib/machines/archbuild/etc/ca-certificates/extracted/cadir/ | head
```

应当看到大量 `.0` 链接文件。

### 容器内网络不通

检查宿主机网络。nspawn 默认使用宿主机的网络命名空间，通常无需额外配置。

### `--bind` 报目标路径已存在

容器内的挂载点必须不存在或为空目录。换个路径，或先在容器内清空。
