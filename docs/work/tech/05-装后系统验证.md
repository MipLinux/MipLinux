# 技术细节 05 · 装后系统验证（真机）

> 目标：把 [05-测试方法](../../knowledge/05-测试方法.md) 第 7 节里 QEMU 测不了的那几项
> —— **NVIDIA 驱动加载**、已有 ESP 与双系统、EFI 固件差异 —— 在真机上验掉。
> 这是项目里风险最高的一项（[work/README](../README.md)），所以**不等安装器**：
> 先在 Live 里把「驱动 + 桌面」跑通；装后系统那半段已随安装器 M1 开验（见第 3 节）。
>
> **纪律（09-19 定下）：** NVIDIA 真机验证要做**两次** —— 第一次验「Live 能加载驱动」，
> 第二次验「装完的系统能用」。**第一次通过不等于目标达成。**
>
> **安全：** 真机上只做「从 U 盘启动 Live」这类不写盘的操作；Live 里的改动全在内存 overlay。
> 分区逻辑永远只在 `out/target.qcow2` 上跑（[05-测试方法](../../knowledge/05-测试方法.md) 第 8 节）。

## 0. 测试机与判据

| 项 | 值 | 出处 |
|---|---|---|
| 显卡 | NVIDIA RTX 5060 Max-Q / Mobile（GB206M，Blackwell，`10de:2d59`）+ Intel Raptor Lake-S 核显（`8086:a78b`） | `lspci -nn \| grep -iE 'vga\|3d'` |
| 覆盖判定 | Blackwell 属 Turing 及更新 → 在支持范围内 | [04-架构决策](../../knowledge/04-架构决策.md) 第 1.7 节 / D8 |

**混合显卡的含义（直接影响判据）：** 屏幕挂在核显上，N 卡是 PRIME 从卡。
所以「驱动能亮」= 模块加载 + modeset 生效 + `nvidia-smi` 认卡 + 合成器**强制跑在 N 卡上**不崩，
**不等于**「画面由 N 卡输出」。判据写成「画面由 N 卡输出」的地方，这台机器上永远验不出来。

## 1. 准备

### 1.1 构建一张带驱动的 ISO

09-22 起 Live 清单（`profile/packages.x86_64`）里有 `nvidia-open` + `nvidia-utils`
（装后系统装什么由装后基础清单 + 用户在安装器里勾选的应用决定，见 [06 P10](../../knowledge/06-待定事项.md)），
所以产物自带驱动，Live 里不需要现装：

```bash
sudo ./scripts/mipl.sh build        # 产物：out/miplinux-<当天日期>-x86_64.iso
```

> **构建是否可用：** 首选用上面这条命令重建 —— 产物自带驱动，第 2 节的判据可以直接跑。
> 若构建暂时不可用（管线又坏了、或当前会话拿不到 root），退回 1.3 的备选路径。

### 1.2 写进 U 盘

本机是 **Ventoy** 盘（`sda`，`sda1` 挂在 `/run/media/ye/Ventoy`）：把 ISO **拷进 Ventoy 分区**即可，
不用 `dd`，也不会碰分区表。

非 Ventoy 盘才用 `dd`（**先 `lsblk` 三次确认盘符，写错盘不可逆**）：

```bash
sudo dd if=out/miplinux-<日期>-x86_64.iso of=/dev/sdX bs=4M status=progress oflag=sync
```

### 1.3 备选路径：用 09-21 的 ISO（Live 里现装驱动）

构建被挡着时（见 1.1 的说明）用 `out/miplinux-2026.09.21-x86_64.iso`。它**不是**当前树，
差别只有三处，第 2 节的判据全部照用：

| 步骤 | 09-21 的 ISO 上怎么做 |
|---|---|
| 联网 | `iwctl` → `device list` → `station <接口> connect "<SSID>"`（会提示输密码）；接上后由 systemd-networkd 发 DHCP。**这张 ISO 上是 `iwd`，不是 `NetworkManager`** —— 它的 motd 是旧的，别照它敲 `nmcli` |
| 装驱动 | ① **先对版本**：`pacman -Sy` 后看 `pacman -Si linux`，其版本必须与 `uname -r` 一致 —— 不一致就别装了（现装的 `nvidia` 模块属于新内核，正在跑的旧内核加载不了），这条路径作废，等构建修好。② `pacman -S nvidia-open nvidia-utils`，**不要 `-Syu`**。③ 装完核对 `pacman -Q linux` 仍等于 `uname -r` |
| 让 nvidia 接管 | 先看 `lsmod \| grep nouveau`：已加载就先 `modprobe -r nouveau` 再 `modprobe nvidia`；`-r` 报 in use 时，下次从 systemd-boot 菜单按 `e` 在 `options` 行尾加 `modprobe.blacklist=nouveau`（这张 ISO 的 `loader.conf` 没关编辑器） |

**证据同样有效：驱动能不能在这块卡上加载，与它从哪来无关。**

> **别在 Live 里做全量升级。** `pacman -Syu` 会把内核换掉，而正在跑的内核**没有**对应的
> `nvidia` 模块，`modprobe` 立刻失败 —— 看起来像「驱动坏了」，其实是版本对不上。
> 现装测试用的包（合成器、终端）时**不要带 `-y`**，用 ISO 自带的 db。
> 若确实 404，先记现象；必须 `-Sy` 时，装完立刻核对 `uname -r` 与 `pacman -Q linux nvidia-open` 是否仍匹配。

### 2.2 驱动到底加载了没有（本半段的重点）

```bash
# ① 模块与黑名单：应当只有 nvidia 系，没有 nouveau
lsmod | grep -E 'nvidia|nouveau'

# ② modeset：期望输出 Y
cat /sys/module/nvidia_drm/parameters/modeset

# ③ 设备认没认：期望打印卡型号、驱动版本 615.71.09、显存大小
nvidia-smi

# ④ 内核绑定关系：期望 Kernel driver in use: nvidia
lspci -k -s 01:00.0 | grep -A3 'Kernel driver'

# ⑤ 内核自己的说法：期望没有 "module verification failed" / "no such device"
dmesg | grep -iE 'nvidia|nouveau' | head -20
```

| 判据 | 通过条件 |
|---|---|
| 模块加载 | `nvidia` / `nvidia_drm` / `nvidia_modeset` / `nvidia_uvm` 在 `lsmod` 里 |
| nouveau 不抢 | `lsmod` 里没有 `nouveau`（`nvidia-utils` 的 `/usr/lib/modprobe.d/nvidia-utils.conf` 负责，见 04 §1.5.1） |
| modeset 生效 | `Y`（**默认值就是 1**，不需要引导参数 —— 见第 4 节） |
| 用户态可用 | `nvidia-smi` 能列卡，版本 615.71.09 |

### 2.3 桌面试跑：niri 与 Hyprland（P5 的证据）

只测三件事：**驱动能亮、输入法能打字、中文能显示**。谁先跑通谁就是基线。

```bash
# 合成器不在 ISO 里（Live 只要极简 + 安装器），试跑时现装进内存 overlay
pacman -S niri hyprland foot     # 不带 -y，见 1.1 的警告
niri --version; Hyprland --version

# 从 TTY 起（Live 是 getty 自动登录的 tty1）
niri                             # 或 niri-session
Hyprland                         # 或 start-hyprland；换 run 之前先退干净上一个大写
```

**同一台混合显卡机器上，「跑起来」和「跑在 N 卡上」是两件事**，两轮都要记：

| 轮次 | 目标 | 怎么做 |
|---|---|---|
| R1 基线 | 合成器能起、不崩 | 默认 GPU（大概率核显），什么都不设 |
| R2 强制 N 卡 | 验 D4 / D8 的前提：NVIDIA + Wayland 真能配合 | 用合成器自己的机制指定 DRM 设备 |

> **R2 的具体变量待现场确认。** 各合成器的写法不同且在演进（Hyprland 是 aquamarine 后端、
> niri 有自己的多 GPU 逻辑），本次尝试时**以 Live 里装到的那个版本的官方文档为准**
> （`man niri`、Hyprland 随包或官方 wiki），并把**实际用了什么**记进下表 ——
> 不要凭记忆抄一份网上看来的变量，那是 Issue #7 / #8 那类错误的翻版。
>
> 判断「跑在哪张卡上」的办法：合成器日志里挑 DRM 设备的行、`/dev/dri/by-path` 的对应关系
> （`ls -l /dev/dri/by-path/`）、以及 `nvidia-smi` 里有没有该合成器的进程。

> **09-22 决定：这一段不在 Live 里做，改到装后系统。** 两个原因：Live 的可写层默认只有
> 256 MiB（见 2.6），现装合成器要先绕内核参数；而装后系统才是用户真正会用的环境。
> R1 / R2 的设计照旧适用，只是搬到第 3 节去执行。

### 2.6 坑：Live 里装不下东西 —— 可写层默认只有 256 MiB

**症状：** `pacman -S niri hyprland` 报空间不足（容易被读成「内存不足」，但这台机器有 31 GiB 内存）。

**根因：** archiso 把可写 overlay 建在 tmpfs 上，大小由内核参数 `cow_spacesize` 决定，**默认 256 MiB**。
initramfs 里 `hooks/archiso` 第 231 行的原文：

```sh
cow_spacesize="$(getarg 'cow_spacesize' '256M')"
```

**解法：** 引导时把它调大。这张 ISO 的 `loader.conf` 没关掉编辑器，所以在 systemd-boot 菜单里按 `e`，
在 `options` 行尾追加 `cow_spacesize=8G`，再回车启动；进去之后照旧 `pacman -Sy niri hyprland foot`
（仍然**不要 `-Syu`**）。

**副产品：** 凡是「在 Live 里现装点什么」的验证都要先加这个参数，否则得到的是假的「空间不足」。

### 4.1 `nvidia_drm.modeset` 的默认值就是 1

```
$ modinfo -p nvidia_drm | grep -i modeset
modeset:Enable atomic kernel modesetting (1 = enable (default), 0 = disable) (bool)

$ cat /sys/module/nvidia_drm/parameters/modeset
Y

$ grep -rn modeset /usr/lib/modprobe.d/ /etc/modprobe.d/
（无匹配）
```
