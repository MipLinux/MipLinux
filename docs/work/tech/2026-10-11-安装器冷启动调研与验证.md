# 安装器冷启动调研与验证

实验日期：2026-10-10、2026-10-11。关联 [#53](https://github.com/MipLinux/MipLinux/issues/53)、[#118](https://github.com/MipLinux/MipLinux/pull/118)。完整 ISO 对照基于 `ce3aef4`，修正版仅增加本次构建 profile 改动。

## 结果与范围

QEMU 中，字体目录时间戳统一并预生成缓存、根 SquashFS 使用 Zstd 后，从光标出现到欢迎页可见约为 3.38 / 3.17 秒；未修改版暗色主题对照约为 18.33 秒。整份 ISO 增大约 190 MiB（8.1%）。

字体扫描与压缩文件冷读取都有受控实验支持。构建侧同时复现了缓存生成后被判无效删除的问题：必须让字体目录、缓存和 SquashFS 内的时间戳一致。

验收到 Live 自动启动和中文欢迎页可见。完整安装、装后启动、真机 NVIDIA 和交互就绪时间未实测。10 月 10 日的子集实验与 10 月 11 日的完整 ISO 冷引导使用不同计时起点，不能混用。

## 10 月 10 日：隔离冷读取与字体扫描

本轮在 10 月 8 日 ISO 的 Live 内存层替换文件来源。计时起点为 launcher 的 electron-exec，**不是光标出现**；未更改目标磁盘。

### 实验条件

- ISO：`out/miplinux-2026.10.08-x86_64.iso`
- 前序记录的 ISO SHA256：`ac252ea6da541188908cb72a8b35bbafaceba6f4dfbdeefa1261a73364de7905`。
- QEMU / KVM，4 vCPU，4 GiB，virtio GPU，软件渲染；通过仓库 mipl.sh 和 pkexec 启动。
- 诊断用 main 与 launcher 加计时，固定 light 主题；各组共用，保留 GPU 日志流程及约 700 ms 延迟。
- 常规组已有字体缓存，每组停止安装器后 sync、drop_caches=3，再启动；空缓存组单独标明。这是同一 VM 中冷文件缓存的重复启动，不等于每组独立冷引导。
- 187 个运行时/共享库文件共 602044854 字节。XZ 与 Zstd 镜像使用相同文件，实验阶段逐文件 SHA256 对照；清单在 file-hashes.json。
- 两份压缩镜像都放在 guest tmpfs，以相同 1 MiB block 和 threads=single 挂载。XZ 使用 x86,arm64 BCJ、1 MiB 字典；Zstd level 15。运行顺序 XZ、Zstd、Zstd、XZ。
- 三份字体为 NotoSansCJK 的 Bold、Medium、Regular TTC；字体哈希在 font-hashes.json。

### 机制证据

- 原 ISO 主进程在 main 之前的采样显示大量内核 CPU 消耗，等待点出现 squashfs_decompress；将运行时和实际映射共享库放入 RAM 后，进入 main 从约 5.3 秒降至约 0.22 秒，恢复后回到约 5.4 秒。
- strace 日志中，有字体缓存时记录到 3 个不同字体文件路径；空缓存时记录到 690 个。空缓存 + Zstd 运行时/库 + 原 ISO 字体的跟踪组进入 main 为 11.527 秒，window-show 为 15.139 秒。**strace 有额外开销，该组用于机制分析，不能与未跟踪组直接计算加速比例。**
- 原 ISO 字体缓存仅有 CACHEDIR.TAG；缓存缺失的构建侧复现见下文。
- GPU 查询返回本身在毫秒量级；当前结果不足以把 D-Bus 错误日志认定为主要等待原因，也不等于排除所有硬件上的 GPU 问题。

### 截图计时和排除项

screen-watch.py 每约 0.21 秒通过 QMP 抓屏。先观察暗屏，再用亮度与蓝色面积条件检测欢迎页，并人工检查保存的 PNG。clock-sync.json 中五次主客时钟对照，最短 RTT 约 23 ms，对应 host monotonic - guest monotonic 为 3864.525064 秒。截图时间有约一个采样周期及抓屏往返的不确定性；未完成实验末尾的第二次时钟校准，因此保留近似口径。

xz-1 与 zstd-1 使用过早期仅亮度检测，捕获空白窗口，其截图不用于内容计时。cached-2 因部分 bind mount 未卸载而仍读取 RAM 文件，排除。初次 strace 携带的 host libc 导致 SIGILL 的尝试也排除；后续使用 guest loader/libc 成功采集。以上均未混入有效对照。


187 文件子集的 XZ 镜像为 183152640 字节，Zstd 为 218185728 字节，增大约 19.1%；三字体 Zstd 镜像为 42680320 字节。子集比例不能用于推算整份 ISO。

## 10 月 11 日：构建修复与完整 ISO 验证

修复使用现有包和工具，在构建装包结束后统一字体目录时间戳、生成缓存并检查非空。构建专用钩子和辅助脚本成功后移除。Live 启动无需运行这套构建脚本。

### 新定位的原因

首次完整构建证实：fc-cache --force 返回成功，但清理阶段将刚生成的所有缓存判无效并删除，ISO 中只剩 CACHEDIR.TAG。

最小 fontconfig 实验复现：SOURCE_DATE_EPOCH 早于字体目录时间时，生成后缓存为空；将目录时间改为相同 epoch 后，缓存保留，去掉 SOURCE_DATE_EPOCH 的运行期 FcDirCacheValid 检查也通过。本地复现日志位于 `out/cache-repro/`。

[fontconfig 官方说明](https://fontconfig.pages.freedesktop.org/fontconfig/fontconfig-user.html)说明 SOURCE_DATE_EPOCH 会参与缓存时间戳计算。本修复统一目录与缓存时间，同时处理 SquashFS 目录没有纳秒精度的问题。

### 已完成静态与构建检查

- 工作草案格式、profile 品牌、bash/sh 语法、git diff --check 通过。
- 修正版完整构建成功；fixed-superblock.txt 确认 Compression zstd。
- fixed-cache-list.txt：五份实际 .cache-12 文件及兼容版本软链接；构建 hook、辅助脚本均未留在 ISO。
- ISO 品牌检查 **未通过**：整张 ISO 的 strings 扫描把 SquashFS 内上游包字符串当成未压缩引导品牌。三处命中已在提取的 fixed.sfs 中逐一复现；卷标、publisher/application 检查通过。误报已单独记录，检查脚本不属于本次修复范围。
- build-fix.log 为失败方案（缓存仍空）的构建记录；build-fix-v2.log 为时间戳修正后的构建记录。构建有 initramfs 可选硬件固件缺失警告，未据此声称对应硬件可用。

### 验收范围

QEMU 4 vCPU / 4 GiB / KVM / virtio，UEFI，无目标磁盘。每次重新启动进程与独立固件变量。有效重复组 RTC 设为 04:00 UTC，保持暗色主题；control-1 为亮色主题，单列为补充结果。测试不改 ISO 内安装器代码。欢迎页由定期 QMP 截图检测，鼠标由 VNC 光标更新事件记录，需要结合保存的截图判断。QMP 采样间隔约 0.2–0.3 秒；光标来自 VNC RichCursor 消息（已人工核对为箭头），两者均使用宿主 monotonic 时钟，无需跨时钟换算。

未做安装、装后重启与真机 NVIDIA 验收。宿主机文件缓存没有全局清空；来宾每次均为新建 VM，避免重复启动共用来宾页缓存。对照使用同日相同软件包版本的主线 profile。

## 复测入口与证据位置

本次 QMP/VNC 采样驱动通过 `scripts/mipl.sh qemu` 启动虚拟机。欢迎页检测同时覆盖亮色、暗色，保存后人工核对中文内容；`window-show` 事件只作诊断参考。运行期通过 `FcDirCacheValid` 检查缓存可用性，并比对可写层与只读 ISO 缓存的 SHA256。
