# 03 · 项目结构

> 这篇文档说明 profile 的每个文件承担什么职责，以及本项目应该如何组织它们。

---

## 1. profile 就是「源代码」

一个 profile 目录的全部内容如下（以官方 `releng` 为参考）：

```
profile/
├── profiledef.sh          ← 发行版身份 + 构建行为
├── packages.x86_64        ← Live 环境装什么
├── bootstrap_packages     ← bootstrap 模式装什么（本项目不用）
├── pacman.conf            ← 从哪些源装
├── airootfs/              ← 叠加进 Live 根文件系统的文件
│   ├── etc/
│   └── usr/local/bin/
├── efiboot/               ← UEFI 引导配置
│   └── loader/entries/*.conf
├── syslinux/              ← BIOS 引导配置
└── grub/                  ← GRUB 引导配置
```

**就这些。** 没有第五个输入。

## 2. `profiledef.sh`

发行版的身份定义。下面是 **releng 的实际内容**（留着的意义是：改坏了可以对照）：

> **MipLinux 的取值已经不同**（A6 改名）：`iso_name="miplinux"`、
> `iso_label="MIPLINUX_<YYYYMM>"`、`iso_publisher="MipLinux <https://github.com/MipLinux/>"`、
> `iso_application="MipLinux Live/Install Medium"`。**以 `profile/profiledef.sh` 为准**，
> 一条命令能看全：
>
> ```bash
> ./scripts/check-identity.sh      # 不需要 root
> ```

```bash
iso_name="archlinux"
iso_label="ARCH_$(date --date="@${SOURCE_DATE_EPOCH:-$(date +%s)}" +%Y%m)"
iso_publisher="Arch Linux <https://archlinux.org>"
iso_application="Arch Linux Live/Rescue DVD"
iso_version="$(date --date="@${SOURCE_DATE_EPOCH:-$(date +%s)}" +%Y.%m.%d)"
install_dir="arch"
buildmodes=('iso')
bootmodes=('bios.syslinux'
           'uefi.systemd-boot')
pacman_conf="pacman.conf"
airootfs_image_type="squashfs"
airootfs_image_tool_options=('-comp' 'xz' '-Xbcj' 'x86,arm64' '-b' '1M' '-Xdict-size' '1M')
bootstrap_tarball_compression=('zstd' '-c' '-T0' '--auto-threads=logical' '--long' '-19')
file_permissions=(
  ["/etc/shadow"]="0:0:400"
  ["/root"]="0:0:750"
  ["/root/.automated_script.sh"]="0:0:755"
  ["/root/.gnupg"]="0:0:700"
  ["/usr/local/bin/choose-mirror"]="0:0:755"
  ["/usr/local/bin/Installation_guide"]="0:0:755"
  ["/usr/local/bin/livecd-sound"]="0:0:755"
)
```

### 变量说明

| 变量 | 作用 | 本项目注意 |
|---|---|---|
| `iso_name` | ISO 文件名前缀 | 已改为 `miplinux`（A6），产物名本身就是验收标准 |
| `iso_label` | ISO9660 卷标 | **不参与引导参数**：引导项用的是 `%ARCHISO_UUID%`（构建时生成的时间戳 UUID）。卷标只写进 ISO 元数据和 ISO 里的 `grubenv`（`ARCHISO_LABEL=`，供 GRUB/loopback 路径使用），**没有任何引导配置文件引用它**。约束：≤32 字符、只允许 `A-Z 0-9 _` |
| `iso_publisher` | 发布者 | 品牌化项 |
| `iso_application` | 应用描述 | 品牌化项 |
| `iso_version` | 版本号 | 默认按日期生成 |
| `install_dir` | ISO 内的目录名 | 影响引导配置中的 `%INSTALL_DIR%` |
| `buildmodes` | 构建模式 | 本项目用 `('iso')` |
| `bootmodes` | 引导方式 | 见第 5 节 |
| `pacman_conf` | 用哪个 pacman 配置 | **见第 4 节的陷阱** |
| `airootfs_image_type` | 根文件系统镜像格式 | 见下 |
| `airootfs_image_tool_options` | 压缩参数 | 影响体积与构建时间 |
| `file_permissions` | **必须声明的权限表** | 见 2.2 |
| `bootstrap_tarball_compression` | bootstrap 模式压缩方式 | 本项目不用 |

### 2.1 `airootfs_image_type` 的可选项

源码中支持三种，各自需要不同的宿主机工具：

| 类型 | 需要工具 | 说明 |
|---|---|---|
| `squashfs` | `squashfs-tools` | releng 默认，通用 |
| `ext4+squashfs` | `e2fsprogs` + `squashfs-tools` | 先做 ext4 镜像再压 |
| `erofs` | `erofs-utils` | 较新，解压性能好 |

**本项目建议先用 `squashfs`**，与官方一致，出问题容易对照。

### 2.2 `file_permissions` 是必需的，不是可选

回顾 `mkarchiso` 的行为：复制 `airootfs/` 时使用

```bash
cp -af --no-preserve=ownership,mode
```

**属主和权限被故意丢弃**，然后按 `file_permissions` 逐个还原。

**规则：任何需要特定权限的文件，都必须在 `file_permissions` 里声明。** 漏了不会报错，只会静默地以错误权限存在于 ISO 里。

`/etc/shadow` 是典型例子——权限错了，Live 环境的 SSH 就起不来。

## 3. 包清单

### 3.1 两份清单

| 文件 | 用途 | 本项目 |
|---|---|---|
| `packages.x86_64` | `iso` 模式，即 Live 环境 | ✅ 主要工作对象 |
| `bootstrap_packages` | `bootstrap` 模式，产出一个 tar | ❌ 不使用 |

releng 的 `bootstrap_packages` 只有两行：

```
arch-install-scripts
base
```

### 3.2 releng 的 129 个包是什么

实测其内容：**全部是命令行工具和系统基础设施**。

包括 `alsa-utils`、`btrfs-progs`、`cryptsetup`、`parted`、`grub`、`efibootmgr`、`linux`、`linux-firmware`、`networkmanager` 的替代品（`iwd`/`dhcpcd`/`wpa_supplicant`）、编辑器和终端工具等。

**缺失的关键项：**

```
plasma / gnome / hyprland     ✗   没有桌面环境
sddm / gdm / lightdm          ✗   没有显示管理器
nvidia-open / nvidia-utils    ✗   没有 N 卡驱动
fcitx5*                       ✗   没有输入法
noto-fonts-cjk / wqy-*        ✗   没有中文字体
firefox / chromium            ✗   没有浏览器
pipewire                      ✗   没有音频服务
archinstall                   ✓   唯一现成的安装器相关组件
```

## 4. `pacman.conf` 与镜像源

### 4.1 必须避开的陷阱

releng 的 `pacman.conf` 用的是：

```ini
[core]
Include = /etc/pacman.d/mirrorlist
```

`mkarchiso` 在**宿主机上**解析这个 `Include`，因此它读取的是**宿主机的镜像列表**。

**后果：** 在 CachyOS 上构建会静默产出「CachyOS 源做出来的 ISO」。

### 4.2 本项目的处理方式

**不使用 `Include`，直接写死 `Server` 行。**

这样有两个收益：

1. 构建结果不依赖宿主机，你与使用 Fedora 的协作者产物一致
2. 顺便完成「中文用户需要国内镜像」这一核心目标

```ini
[core]
Server = https://mirrors.tuna.tsinghua.edu.cn/archlinux/$repo/os/$arch

[extra]
Server = https://mirrors.tuna.tsinghua.edu.cn/archlinux/$repo/os/$arch
```

**注意 `$repo` 和 `$arch` 是 pacman 的变量，必须保留。**

已验证可用的国内镜像：

- 清华 TUNA：`https://mirrors.tuna.tsinghua.edu.cn/archlinux/`
- 中科大 USTC：`https://mirrors.ustc.edu.cn/archlinux/`
- 阿里云：`https://mirrors.aliyun.com/archlinux/`

**同一个 `pacman.conf` 需要被安装器复用**，以保证装出来的系统也使用国内源。这是「Live 与装后系统一致」原则在镜像源上的具体体现。

### 4.3 签名

`pacman.conf` 中有：

```ini
SigLevel    = Required DatabaseOptional
```

意味着包签名会被校验。**安装器写入目标系统后，必须确保 `pacman-key --init` 和 `--populate archlinux` 正确执行**，否则用户装完第一次 `pacman -Syu` 就会失败。这是自制发行版的经典长期故障。

## 5. 引导配置

### 5.1 releng 用的是什么

```bash
bootmodes=('bios.syslinux'
           'uefi.systemd-boot')
```

- **BIOS** → syslinux，配置在 `syslinux/`
- **UEFI** → systemd-boot，配置在 `efiboot/loader/`

**注意：`grub` 在包清单里，但它不是 ISO 的引导器**，而是给安装后的目标系统使用的引导器选项之一。

### 5.2 UEFI 引导项的实际格式

`efiboot/loader/entries/*.conf`：

```
title    Arch Linux install medium (%ARCH%, UEFI)
sort-key 01
linux    /%INSTALL_DIR%/boot/%ARCH%/vmlinuz-linux
initrd   /%INSTALL_DIR%/boot/%ARCH%/initramfs-linux.img
options  archisobasedir=%INSTALL_DIR% archisosearchuuid=%ARCHISO_UUID%
```

三个占位符由 `mkarchiso` 在构建时替换：

| 占位符 | 来源 |
|---|---|
| `%ARCH%` | 架构，如 `x86_64` |
| `%INSTALL_DIR%` | `profiledef.sh` 的 `install_dir` |
| `%ARCHISO_UUID%` | 构建时生成的 ISO 标识 |

**`options` 行是 N 卡驱动的关键位置之一** —— 内核参数要加在这里（以及 syslinux 对应文件里）。

### 5.3 GRUB 配置

`grub/grub.cfg` 和 `grub/loopback.cfg` 存在，但默认 `bootmodes` 未启用 GRUB 引导 ISO。

## 7. 贯穿全局的三条约束

### 7.1 包清单必须单一来源

Live 环境和安装器写盘时使用的包清单**必须是同一份文件**。

否则会出现「Live 里中文能打字、装完不能」这类极难定位的问题。这是 [01-概念模型.md](01-概念模型.md) 中「Live 与装后系统必须一致」原则的具体落地。

### 7.2 `airootfs` 是唯一的注入手段

Live 环境的「出厂设置」——字体配置、输入法环境变量、桌面默认配置、镜像源——**只能通过 `airootfs/` 注入**。

放进 `airootfs/` 的内容会被原样叠加进 squashfs。不要试图在构建后修改 ISO，那不可复现。

### 7.3 内核参数在引导配置里，不在包里

`nvidia_drm.modeset=1` 这类参数必须写进 `efiboot/loader/entries/*.conf` 和 `syslinux/` 对应文件。

没有哪个包会自动帮你设置它（详见 [04-架构决策.md](04-架构决策.md) 第 1.5.2 节）。
