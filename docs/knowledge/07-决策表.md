# 07 · 决策表

> D 编号是**决策史**：一个决定一个号，改主意不换号、不销号。
> 本表是 D 编号的唯一出处 —— 一条一行结论，「理由 / 去处」列给展开与落地。
> 新增 D 编号由维护者点头，从当前最大号续起（规则见 [docs/AGENTS.md](../AGENTS.md)）。
> 还没定的问题（P 编号）见 [06-待定事项.md](06-待定事项.md)。

---

| 编号 | 决策 | 理由 / 去处 |
|---|---|---|
| D1 | 构建基底用官方 `archiso` + `releng` profile | 不 fork CachyOS-Live-ISO，避免绑定他人仓库 |
| D2 | 构建在纯净 Arch 环境（`systemd-nspawn`）里进行 | [02-环境与工具链.md](02-环境与工具链.md) 第 1.3 节 |
| D3 | 不使用宿主机 `pacman.conf` 的 `Include` 隐式解析 | 否则会静默引入宿主发行版的源；落地形态见 [profile/AGENTS.md](../../profile/AGENTS.md) |
| D4 | 内核用官方 `linux`，NVIDIA 驱动用 `nvidia-open` | `nvidia-open` 硬绑官方内核，零额外工作拿到预编译模块；展开见 [04-架构决策.md](04-架构决策.md) 第 1.4 节 |
| D5 | 不挂载 CachyOS 或其它第三方软件源 | 与项目目标冲突，且破坏构建的确定性；展开见 [04-架构决策.md](04-架构决策.md) 第 1.2 节 |
| D6 | Live 与装后系统分别维护受版本控制的包清单，安装器读取装后清单 | 避免「Live 里能用、装完不能用」的不一致；展开见 [04-架构决策.md](04-架构决策.md) 第 3.1 节 |
| D7 | 「可变」指滚动更新，交付形态是装到硬盘的传统发行版 | 安装器是必需组件 |
| D8 | 装后系统只覆盖 Turing 及更新架构；Live 为 Pascal 及更老的 NVIDIA 卡保留 nouveau 回退 | `nvidia-open` 已不支持更老架构，无需 legacy 分支；展开见 [04-架构决策.md](04-架构决策.md) 第 1.7 节 |
| D9 | 名称是 MipLinux；ISO 产物名用构建日期，卷标 `MIPLINUX_<YYYYMM>` | 引导项用的是构建时生成的时间戳 UUID，换卷标不需同步改引导配置；取值读 [profile/profiledef.sh](../../profile/profiledef.sh)，一致性断言是 `scripts/check-identity.sh` |
| D10 | 目标范围是**对外发布** | 签名、校验和、中文文档、硬件覆盖都按对外标准做；里程碑见 [installer-roadmap.md](../work/installer-roadmap.md) M5 |
| D11 | ISO 只承载 Live 环境，装系统所需的包在安装时从国内源拉取 | ISO 小、迭代快，并把「默认国内源」变成前提；代价是安装必须联网，联网界面不能省 |
| D12 | Live 是**极简 kiosk**：开机直进安装器，不兼作救援盘 | 路径最短；「极简」不等于不装 —— 联网配置不能省 |
| D13 | 版本号双轨：ISO 产物名用构建日期，语义号 `v0.x.y` 只打在 GitHub Release | 滚动发行版里同一天重建的产物都不同，日期才是产物的真实指纹 |
| D14 | 安装器后端 Python 3、前端 Electron，Live 用 `cage` 做 kiosk 合成器，分区用 `python-pyparted`，联网用 NetworkManager + `nmcli`，装后系统用 systemd-boot；v0.1 只做 UEFI + 整盘擦除 + ext4 单根 | 选型全部落在官方源；整盘场景不需要无损 resize；里程碑见 [installer-roadmap.md](../work/installer-roadmap.md) |
| D15 | 交付桌面用 **Hyprland**，桌面配置取自我们自行维护的 Caelestia fork（[MipLinux/Caelestia](https://github.com/MipLinux/Caelestia)） | 走 WM 路线，不做完整桌面环境；实测判据见 [tech/05](../work/tech/05-装后系统验证.md) 第 2.3 节 |
| D16 | 装后系统默认启用 `[archlinuxcn]` 并校验包签名 | 安装器在安装时把 key 导入目标密钥环，装后系统第一次 `pacman -Syu` 即验签 |
| D17 | 时区名单取运行系统的 `zone1970.tab`；界面不放世界地图；已过审的小表写中文名，表外照实显示 IANA id | tzdata 的时区名本身带政治表述 —— 不撰写、只呈现；显示名改动逐次过审 |
| D18 | 代码与配置按 GPL-3.0-or-later，品牌素材按 CC BY-SA 4.0，名称与商标不随素材授权 | 许可全文见 [LICENSE](../../LICENSE) 与 [README 的「许可」小节](../../README.md#许可)；第三方组件按 [THIRD-PARTY.md](../../THIRD-PARTY.md) 留许可原件与改动说明 |
| D19 | 构建与 Live 从 `[archlinuxcn]` 拉包也校验签名 | 落地形态见 [profile/AGENTS.md](../../profile/AGENTS.md) |
