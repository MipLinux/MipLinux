# 技术细节 06 · 镜像源与联网

> 目标：把 Issue [#18](https://github.com/MipLinux/MipLinux/issues/18)「网络变更时自动更换镜像源」
> 的 **Live 侧**做成一条能复现、能实测的链：网络一变（切 VPN、换 Wi-Fi）就重新测速并重排镜像源。
>
> **范围（I1）：只做 Live 侧。** 装后系统的换源策略是 [#23](https://github.com/MipLinux/MipLinux/issues/23)
> 与 [P11](../../knowledge/06-待定事项.md) 的事 —— 但 `airootfs/` 会被装后系统继承
> （[profile/AGENTS.md](../../../profile/AGENTS.md)），所以脚本靠 Live 标记把自己挡住，见第 2 节。
>
> **状态：未实测。** 到 2026-10-04 为止只有**本机 dry-run（非 Live、非 root）**与静态检查；
> Live 里的真触发（QEMU 里 `nmcli` 上下线 → mirrorlist 真变）**还没跑**。
> 命令在第 4 节 —— 跑完请把输出贴回本文，那时才允许把「未实测」改成「✅」。

## 1. 要管的是「两处源」

只换一半等于没换。Live 里 pacman 读的是：

| 处 | 文件 | 谁在写 | 覆盖的仓库 |
|---|---|---|---|
| ① | `/etc/pacman.d/mirrorlist` | `reflector` | `core` / `extra` / `multilib` |
| ② | `/etc/pacman.d/mirrorlist-archlinuxcn` | 本脚本自己探速 | `archlinuxcn` |

这两份文件都是从 [profile/airootfs/etc/pacman.d/](../../../profile/airootfs/etc/pacman.d/) 出厂的，
安装器会把 `pacman.conf` 里每个 `Include` 的目标一起拷进装后系统
（`installer/backend/mipl_installer/configure.py` 的 `iter_includes`）—— 检查点 6 靠这条。

**为什么 archlinuxcn 这半要自己写**：`reflector` 的数据源是 Arch 官方的 Mirror Status API，
里面没有 archlinuxcn 的镜像。所以这半自己探：顺序下每个镜像 `archlinuxcn.db` 的前 64 KiB，
量字节/秒，按速率重排。

> **不并发探。** 几个镜像同时下，抢的是同一条带宽，测出来的「谁快」是自己制造的假象。

## 2. 怎么接起来的

```
网络变化
  └─ NetworkManager
       └─ /etc/NetworkManager/dispatcher.d/90-mipl-mirror-switch   ← 只判断，立刻返回
            └─ setsid /usr/local/bin/mipl-mirror-switch --trigger up|connectivity-change   ← 后台干活
                 ├─ reflector → /etc/pacman.d/mirrorlist
                 └─ 顺序探速  → /etc/pacman.d/mirrorlist-archlinuxcn
```

四处刻意的设计：

1. **dispatcher 必须立刻返回。** NM 是**同步**等 dispatcher 脚本跑完才继续自己的状态机 ——
   在这里等几十秒测速，换 Wi-Fi 的表现就是「连上了但半天不干活」。所以钩子只做判断，
   真正的活用 `setsid` 甩到新会话里（NM 返回后不会连坐把它收掉）。
2. **重复触发交给锁，不交给钩子。** `up` 与 `connectivity-change` 会连着来，
   脚本自己在 `/run/mipl-mirror-switch.lock` 上 `flock`：拿不到锁的那次直接放过，不排队。
3. **写文件是原子的。** 同目录写临时文件再 `rename` —— pacman 读到的要么是旧的、要么是新的，
   不会有半个 mirrorlist。reflector 的输出先落在临时目录，**校验里面真有 `Server` 行才替换**；
   两半都只比 `Server` 行，列表没变就不落盘（reflector 的表头注释带生成时间，重写只会 churn mtime）。
4. **只有成功才记 stamp。** `/run/mipl-mirror-switch.stamp` 记的是「上次**成功**换源」，
   某半边失败时不写 —— 否则网络刚起来时失败一次，就会被 `--min-interval` 挡 60 秒不准重试。
   日志里那半边会写「失败」，与「没变」分开，别混着读。

### Live 守卫（为什么装后系统上什么都不发生）

`/run/archiso/bootmnt` 存在 = 在 Live 里（archiso 把 ISO 挂在那儿，见
[installer/tests/live-rehearsal.sh](../../../installer/tests/live-rehearsal.sh)）。
装后系统里没有它，脚本于是**一声不响地退出（退出码 0，不写任何东西）**。
[#23](https://github.com/MipLinux/MipLinux/issues/23) 定案后要改的是这个判断，
不是另写一份脚本 —— 装后系统该不该、以什么频率换源，归它管。

### 参数（都能在文件头看到）

| 参数 | 值 | 为什么 |
|---|---|---|
| `REFLECTOR_COUNTRIES` | `CN,HK,TW,JP,SG,KR` | 国内及周边；reflector 只认它的镜像池 |
| `REFLECTOR_LATEST` / `--sort rate` | 最近同步的 30 个里按速率排 | **不加 `--latest` 会去 rate 官方池里所有镜像**，慢得不像话 |
| `REFLECTOR_NUMBER` | 12 | 够用，别把 mirrorlist 撑长 |
| `PROBE_BYTES` / `PROBE_TIMEOUT` / `PROBE_BUDGET` | 64 KiB / 5 s / 45 s | 单镜像与整体的上界；预算用完剩下的按原顺序留在后面 |
| `DEFAULT_MIN_INTERVAL` | 60 s | **成功**换过就不再换（失败不写 stamp，下次触发即可重试），免得网络抖动时反复重排 |

**依赖：不新增任何包。** `reflector` 本来就在 Live 清单里（`profile/packages.x86_64`），
`python3` 因它而存在（D14 也是这么记的，见 [06 P6](../../knowledge/06-待定事项.md)）；
HTTP 探测走 Python 标准库 —— **没有引 `curl` / `wget` / `rate-mirrors`**（根文件红线）。

**已知依赖坑（实测踩到）：** `reflector` 会把 Mirror Status 数据缓存在 `$XDG_CACHE_HOME`。
本机 dry-run 时它直接报 `OSError: [Errno 30] Read-only file system: '<HOME>/.cache/mirrorstatus.json'`
而退出 1。NM 的 dispatcher 环境里 HOME 不保证可写、甚至可能没设 —— 所以调用 reflector 时
**显式把 `XDG_CACHE_HOME` 指到本次的临时目录**，不靠环境里恰好有个能写的家目录。

## 3. 这次动了哪些文件

| 文件 | 是什么 |
|---|---|
| `profile/airootfs/usr/local/bin/mipl-mirror-switch` | 换源本体（Python 3，标准库 + reflector） |
| `profile/airootfs/etc/NetworkManager/dispatcher.d/90-mipl-mirror-switch` | NM 钩子：只判断 + 甩后台 |
| `profile/profiledef.sh` | `file_permissions` 白名单里补上前两个文件 —— 不补，它们进 ISO 就是 644 |

两个文件都必须是 **755、root 属主、组/其他不可写** —— NetworkManager 会跳过权限不对的
dispatcher 脚本。但**git 里的 755 进不了 ISO**：`mkarchiso` 装配 airootfs 时用
`cp -af --no-preserve=ownership,mode` 先把模式重置成 umask 默认，**只**给 `profiledef.sh` 的
`file_permissions` 里列出的路径补回模式（[knowledge/03 §2.2](../../knowledge/03-项目结构.md)）。
所以两个文件必须在那张表里各占一行，否则 ISO 里是 644、钩子根本不触发 ——
Issue [#51](https://github.com/MipLinux/MipLinux/issues/51) 的同款坑
（[archive/2026-09-23-kiosk启动链的两个坑.md](../../archive/2026-09-23-kiosk启动链的两个坑.md) §二）。

**运行时才出现的文件**（都在 `/run`，重启即消失）：

| 路径 | 是什么 |
|---|---|
| `/run/mipl-mirror-switch.log` | 全过程日志。NM 的 stdout 不好捞，QEMU 里 `cat` 这个就是证据 |
| `/run/mipl-mirror-switch.lock` | 同一时刻只允许一次换源 |
| `/run/mipl-mirror-switch.stamp` | 上次**成功**换源的时间，配合 `--min-interval`；某半边失败时不写，所以失败后下一次触发就能重试 |

## 4. 怎么测（跑完把输出贴回本节）

### 4.1 本机 dry-run（不需要 root、不需要 Live）

指向仓库里那两份 mirrorlist，全流程真跑，**一个字节都不写**：

```bash
mkdir -p /tmp/mipl-dryrun
python3 profile/airootfs/usr/local/bin/mipl-mirror-switch --dry-run --force \
    --trigger local-dryrun --run-dir /tmp/mipl-dryrun \
    --mirrorlist-dir profile/airootfs/etc/pacman.d
```

期望：日志里出现每个 archlinuxcn 镜像的实测 B/s、reflector 写出的官方列表、
以及 `[dry-run] 本该写入 …`；跑完 `git status` 应当**没有**任何 mirrorlist 改动。

### 4.2 Live 里的真触发（I1 的验收）

```bash
sudo ./scripts/mipl.sh build     # 构建（会跑品牌断言之前的构建链；不带 --keep-work）
sudo ./scripts/mipl.sh qemu      # 起 Live
```

进了 Live（tty1 或 ssh）之后：

```bash
# ① 开机联网后应当已经自动跑过一次
cat /run/mipl-mirror-switch.log
ls -l /usr/local/bin/mipl-mirror-switch /etc/NetworkManager/dispatcher.d/90-mipl-mirror-switch

# ② 手动看一眼「现在会换成什么」（不写盘）
/usr/local/bin/mipl-mirror-switch --dry-run --force

# ③ 制造一次真正的网络变更（这是 I1 的判据）
head -3 /etc/pacman.d/mirrorlist          # 先记下现在的第一个
nmcli networking off; sleep 3; nmcli networking on

# ④ 等它跑完（测速要几十秒；`--min-interval` 默认 60s，刚跑过就等一下再触发）
sleep 90; cat /run/mipl-mirror-switch.log
head -3 /etc/pacman.d/mirrorlist          # 期望：第一个换成速率最高的那个（可能和原来相同）

# ⑤ 换完的源还得能用（检查点口径）
pacman -Sy                                # 期望：正常同步，不报 failed to synchronize
```

**期望与失败的样子：**

| 现象 | 说明 |
|---|---|
| 日志里 `不是 Live（…）` | 守卫误判，或跑在了装后系统里 |
| `NetworkManager 报告的连通性是 limited` | 网络没真通（QEMU 用户模式网络默认是通的），脚本会**不动** mirrorlist |
| `另一次换源还在跑` | 锁生效，正常 |
| `距上次换源只有 Ns（< 60s）` | 最小间隔生效，正常；要立刻重跑加 `--force` |
| `reflector 退出码 1` | 看它带的 stderr —— 缓存目录、DNS、`archlinux.org` 不通都在这里现形 |

> **不许用「脚本跑了没报错」当验收。** 判据是 ③ 之后 mirrorlist **真的变了**、且 ⑤ 仍然正常
> （[05-测试方法](../../knowledge/05-测试方法.md) 的口径）。

## 6. 已知边界与没做的事

- **装后系统**：脚本在装后系统上是空转（Live 守卫）。策略归 [#23](https://github.com/MipLinux/MipLinux/issues/23) / [P11](../../knowledge/06-待定事项.md)。
- **装后系统的 mirrorlist 是「装的那一刻的 Live 状态」，不是出厂那份**：安装器读的是
  **运行系统**的 `/etc/pacman.conf` 与它 `Include` 的文件
  （`installer/backend/mipl_installer/configure.py` 的 `copy_pacman_config()`，docstring 原话如此），
  所以换源改过的 `/etc/pacman.d/mirrorlist` 会**跟着进装后系统** —— 同一张 ISO 装两次，
  结果可能不同，也可能不是国内镜像。接受现状还是让安装器改读只读的 ISO 挂载点，
  是与 #23 相邻的另一条边界，已按「出界提 issue」另立一条 →
  [#90](https://github.com/MipLinux/MipLinux/issues/90)（2026-10-04 起草并发布）；
  在它定案前，**别把「装后系统一定是国内源」当成这条工作已经保证的事**。
- **⚠️ archlinuxcn 这半现在是「写了但不管用」**：`profile/airootfs/etc/pacman.conf` 的
  `[archlinuxcn]` 段里**写死了 9 行 `Server`，排在 `Include` 之前** —— pacman 按顺序取第一个
  能用的，所以那 9 行永远赢，重排 `mirrorlist-archlinuxcn` 不改变实际行为。
  这两个文件不在 Issue #18 的文件范围内，按「出界提 issue」另立了一条 →
  [#87](https://github.com/MipLinux/MipLinux/issues/87)（2026-10-04 起草并发布）：
  把写死的行收进 `mirrorlist-archlinuxcn`。**在它落地之前，archlinuxcn 的实际源仍是
  `pacman.conf` 里写死的那几个** —— 别把本文档当成那条已经能用的证据。
- **`--min-interval` 是全局的**，不区分「有线换到无线」这种真变更与「同一张网抖动」。
  第一版有意做小；真出现误判再谈。
- **国家集合是 `CN,HK,TW,JP,SG,KR`**，比出厂的 mirrorlist（中国大陆 + 香港 + 日本）宽一档：
  港日韩台新从国内过去都算「周边快源」，而且开 VPN 时最快的往往不是国内镜像 ——
  那正是 Issue #18 要解决的场景。**要严格只在国内挑，就把这个常量改成 `CN`**（一行）。
- **没做**：装后系统的 reflector 策略、`archlinuxcn` 的签名与政策（P11）、
  镜像源的 IP 优选（`--ipv4`）、把结果写进安装器界面。
