## 1. 怎么复现（都不需要 root、不需要 Live）

```bash
# 单测（Node）：步骤表 / 状态机与校验 / i18n 键 / token / logo 资产 / 后端适配层与键位图
node --test "installer/frontend/app/tests/*.test.mjs"

# 单测（Python）：后端核心 + 只读出口的 JSON 协议（键位那组会真读 /usr/share/kbd/keymaps）
python3 -m unittest discover -s installer/tests -t installer

# 只读出口的真机数据面（不动盘、不需要 root；stdout 上恰好一份 JSON）
PYTHONPATH=installer/backend python3 -m mipl_installer --print-disks
PYTHONPATH=installer/backend python3 -m mipl_installer --print-keymap de

# 文案守卫：tech/09 的 §三 + 附 A ↔ renderer/i18n/*.json 逐字比对
python3 installer/frontend/app/tools/i18n.py --check

# 生成物守卫（不许手改生成物）
python3 installer/frontend/app/tools/gen-tokens.py --check     # color.json → palette.css
python3 installer/frontend/app/tools/gen-icons.py --check      # vendor/icons → icons.js

# 设计断言
python3 installer/frontend/app/tools/check-tokens.py           # 色板三方 + token 结构
python3 installer/frontend/app/tools/check-contrast.py         # 对比度
python3 -m unittest discover -s installer/frontend/theme/tests -t installer/frontend/theme

# 界面探针（真 Electron 离屏渲染，逐页渲染 + 截图 + 93 项断言）
MIPL_ELECTRON_BIN=<electron> node installer/frontend/app/tools/probe-render.js
```

`<electron>` 在 Live / 构建容器里就是 `/usr/lib/electron44/electron`（`electron44` 包提供）；
宿主机上可以解包官方 `electron44` 包再指过去（见 §5）。

## 3. ISO 侧：装配与体积（**维护者构建的实测**）

- 产物：`out/miplinux-2026.10.04-x86_64.iso`，**2 865 676 288 B（2.67 GiB）**；
  对照 2026-10-02 的 **2 756 083 712 B（2.57 GiB）** → **+104.5 MiB**，
  与 [06 的已定案索引](../../knowledge/06-待定事项.md) 里离线闭包 + mksquashfs 的估算（≈ +100 MiB）相符。
- 装配核对（读 `arch/x86_64/airootfs.sfs` 的清单，只读）：
  `usr/lib/electron44/**`、`usr/local/lib/mipl-installer/frontend/app/**`
  （`main.js` / `preload.js` / `renderer/{css,js,i18n,assets,vendor}` / `design` / `tools` / `tests`）、
  入口软链 `/usr/local/bin/mipl-installer → …/frontend/mipl-installer` 都在；
  **入口权限是 `0755`** —— 没有踩 Issue #51 那个「进 ISO 变 644 → 203/EXEC」的坑。
- 维护者在该 ISO 上跑过 QEMU 并逐屏点过（普通 8 步 + 高级 12 步），据此提了 7 批界面反馈；
  这些反馈已全部修完（见 §4）。**该 ISO 对应的是修复前的提交。**

## 4. 从实机反馈到修复（都已落成断言）

| 反馈 | 根因 | 守卫 |
|---|---|---|
| 选中 WiFi 后点不到「继续」/ 选高级安装整个应用重绘 | `#root` 没高度 → `.app` 随内容长高 | `#root` = 视口高、动作区在视口内、页面不滚动 |
| 文本可选中 / 图片可拖拽 | 没设 | `user-select` 断言、`draggable` 断言 |
| 动画卡顿、操作延迟 | 启动器**无条件**强制 SwiftShader 软渲染 | 启动器按 GPU 探测；软渲染时进低配模式（断言关掉极光/噪点） |
| 图标与目录数字在 167% 下显得小 | 图标/控件高度是固定 px | 按钮高度、步骤序号、图标缩放断言 |
| 按钮「太扁」、大标题把一屏撑满 | 同上 + 大字号线性缩放 | 大标题缩放放缓断言 |
| 列表贴住搜索框 / 最后一项被渐隐吃掉 | 固定遮罩 + 无间距 | 间距断言、`data-scroll-fade` 四态断言 |
| 搜索框内外两圈焦点线 | 全局 `:focus-visible` 与控件自身光圈叠加 | 焦点只有一层断言 |
| 列表里选中一项就跳回开头（几百条名单里挑一条尤其明显） | `renderPage` 整棵子树重建 → 滚动容器的 `scrollTop` 跟着归零 | 「选中之后列表不回开头」断言（整页确实重画了仍保住位置；停用修复即变红） |
| 时区 / 语言 / 键盘页的**默认值不在第一行**，混在后端给的顺序里 | 名单顺序直接用后端出口的顺序，默认值没有参与排序 | 「默认项在第一行」断言（停用修复即变红）＋「选中别的项不重排」（盯住「把选中项置顶」那个被否掉的方案）＋ `withDefaultFirst` 单测 |
| 网络页不刷新状态，也没有手动刷新入口 —— 网连上了也走不到下一步 | 现状只在 `Backend.load()` 读一次；`9a99666` 把「重新扫描」挪到列表下方时 `disk.js` 挪对了，网络页是**直接删掉**（`?: null`） | 「重新扫描」在列表下方、还在、点了先出「正在扫描」＋「拔网线后界面自己变未连接」「网通了自动解锁」断言（停用轮询即变红） |

**上面十条**：前七条来自实机反馈，末三条是 2026-10-05 在 `feat/installer-real-backend` 上报的
（列表跳回开头 / 默认项不置顶 / 网络页不刷新）。末三条里能红的都逐条核过
「把修复停掉，对应断言就变红」；只有「选中别的项不重排」是**规格锁**（当前实现下不会红，
它挡的是「把选中项提到第一行」那个被否掉的方案）。

**另外，#97 收尾时自审还抓到一条**（它没来得及跑出实机症状，但代码写出来的当天就是错的，
所以没进上面的表）：进度页装失败时会 `ctx.rerender()` 把后端那句话摆出来，
而外壳只要在进度页看到 `failed` 就重置进度状态 —— 重置之后 `startedAt` 没了，
进度页又 `startRun()`，于是**失败会自动重开一轮安装，无限循环**。
那正是这个项目明令禁止的「在残骸上接着装」。判据抽成了
`steps.shouldRestartRun()`（「从别的页走过来」才算重跑，页面自己的重画一律不动状态），
并在 `tests/steps.test.mjs` 里钉住 —— `app.js` 在 Node 里 import 不了（顶层就读 `window`），
抽出来才测得到。
