**收口情况（同日补记）：** 两处断点都已修复并实测。实际挖出来的是**四处**，比这张表里写的多两处 ——
除了「入口路径」与「没有 shebang」，还有「执行位被 `mkarchiso` 重置」（ISO 里是 `644`，
所以 #51 里那句 `Permission denied` 不是别的 errno，是**真的没有执行位**）
和「`cage` 拿不到 seat」（`libseat` 的 seatd / logind 两个后端都不通）。
四个坑的症状都是「窗口不出来」，互相把对方盖住，所以修一层就得重新实测一次。
完整记录见 [archive/2026-09-23-kiosk启动链的两个坑.md](../archive/2026-09-23-kiosk启动链的两个坑.md)。

**已实测：** `mipl build` 恢复；重建后 ISO 里两个入口为 `755`；QEMU 里开机**不碰键盘**窗口自动出现。
**未实测：** #51 验收里另外两条（`systemctl kill` 落回 TTY、`journalctl -u` 干净）；
`mipl.sh installer` 那条 `--vga virtio` 路径（出窗口那次走的是 `mipl.sh qemu` 的默认显卡）。

**M2 不切开：** 前端整条留在**线 G**（少一次协调、少一批撞车）；

网络一变就测速换源。

- **I1**【必做】[#18](https://github.com/MipLinux/MipLinux/issues/18) 的第一版，**只做 Live 侧**：
  NetworkManager dispatcher（`up` / `connectivity-change`）触发 → 测速排序 → 写 mirrorlist。
  三条约束，动手前先读：
  1. **不新增依赖**（根文件红线）：`reflector` 与 `python3` 都已经在 Live 清单里（D14 也是这么写的），用它俩 ——
     不要引 `curl` / `rate-mirrors` 这类新包
  2. **两处源要一起管**：`airootfs` 的 `pacman.conf` 里写死了 `Server`，mirrorlist 只是另一半
     —— 09-19 线 C 是两处都写（见 [2026-09-19.md](2026-09-19.md)），只换一半等于没换
  3. **只在 Live 侧**：装后系统的 reflector 策略是 Issue #23 与 P11 的事，**先不碰**

  验收：QEMU 里用 `nmcli` 上下线触发，mirrorlist 真的变了，之后 `pacman -Sy` 仍然正常；

  这正是 09-18 线 B 的交叉验证用意：两边结果一致，才说明流程真的可复现

  先查它与 D4「官方内核」是否冲突）与 [#44](https://github.com/MipLinux/MipLinux/issues/44)
  （nouveau 覆盖口径 —— 按规矩先以 P 编号进 06 走推导）各写一份「最小可验证一步」。
