## 1. 启动链：从开机到窗口

```
UEFI 固件
  └─ /loader/entries/01-archiso-linux.conf        ← systemd-boot，cmdline 见下
       └─ 内核 + initramfs（archiso 钩子）
            └─ 挂载 /dev/sr0 → /run/archiso/bootmnt，airootfs.sfs → /run/archiso/airootfs
                 └─ systemd
                      └─ mipl-installer.service（enabled，multi-user.target.wants/）
                           └─ ExecStart=/usr/local/bin/mipl-kiosk
                                └─ 软链 → /usr/local/lib/mipl-installer/frontend/mipl-kiosk
                                     └─ seatd-launch → cage（kiosk Wayland 合成器）
                                          └─ /usr/local/bin/mipl-installer（软链 → frontend/）
                                               └─ PySide6 全屏窗口
```

cmdline 里与测试相关的两项（由 `mkarchiso` 生成，构建时的时间戳 UUID）：

```
archisobasedir=arch archisosearchuuid=<时间戳>-00 console=tty0 console=ttyS0,115200
```

- `archisosearchuuid` 必须与 ISO 上 `/boot/<uuid>.uuid` 的**文件名**逐字一致
  （文件内容是空的，靠名字匹配）—— 对不上就找不到 ISO。换 ISO 后别拿旧参数硬套；
- `console=ttyS0,115200` 是串口日志能用的前提（见 §4）。

### 1.1 三层入口，各自的存在理由

| 层 | 路径 | 为什么要有它 |
|---|---|---|
| unit | `profile/airootfs/etc/systemd/system/mipl-installer.service` | 出事时 systemd 管重启与日志（检查点 2 的判据就在 `journalctl -u` 里） |
| 脚本 | `frontend/mipl-kiosk` | 起 `seatd-launch` + `cage`；**不能直接 exec cage**（见 §1.2） |
| 界面 | `frontend/mipl-installer` | PySide6 入口。M2 起会退化成薄壳，真界面在 `mipl_installer_qt` |

**三者都必须有 shebang 且可执行。** 少了任何一样，systemd 一律只报 `203/EXEC`，
而 `203/EXEC` 背后可能是三种不同的 errno（`ENOENT` 悬空软链 / `ENOEXEC` 没 shebang /
`EACCES` 没有执行位）—— 排查见 [archive/2026-09-23-kiosk启动链的两个坑.md](../../archive/2026-09-23-kiosk启动链的两个坑.md) §七。

### 1.2 为什么要过 `seatd-launch`

`cage` 基于 wlroots，起 DRM 会话要先经 `libseat` 拿一个 seat。`libseat` 有两个后端，
在 Live 里**两个都不通**：`seatd` 守护进程没运行（`/run/seatd.sock` 不存在），
`logind` 后端要求调用方有登录会话（systemd 服务没有）。

`mipl-kiosk` 因此写的是：

```bash
exec /usr/bin/seatd-launch -- /usr/bin/cage -- /usr/local/bin/mipl-installer
```

`seatd-launch` 起一个专用 seatd、**等它就绪**、再把 cage 跑起来（结束后收掉 seatd）。
绕开它的表现很有迷惑性：`cage` 每次都在 **0.000 秒**必败，靠 `Restart=on-failure` 无限重试，
看起来像「启动很慢」，其实是确定性失败。

> `seatd` 由 `wlroots0.20`（cage 的依赖）间接装进 Live，**不在 `packages.x86_64` 里**。
> 谁要裁包，先看这一条。

### 1.3 与 `getty` 的关系（检查点 2 的兜底）

unit 里有 `Conflicts=getty@tty1.service`，所以安装器一起来，tty1 上的 autologin getty 就让位。
**`getty` 的 autologin 不是「怎么进安装器」的答案，它是兜底**：安装器挂了或被 kill 掉，
tty1 还能拿回来敲命令 —— 这条本身是检查点 2 的一部分（见 §3 第 3 步）。

## 2. 三条起 VM 的命令，选哪条

**都走脚本，不要手抄 qemu 命令行**（Issue #7、#8 的教训）。

| 命令 | 干什么 | 什么时候用 |
|---|---|---|
| `mipl.sh qemu` | 只起 Live，不挂盘 | 看启动链、检查点 1 / 2 |
| `mipl.sh installer` | **装系统测试一条龙**：目标盘缺了才建 + 挂上 + 串口日志自动落盘 | 跑检查点 3–6 |
| `mipl.sh qemu --disk out/target.qcow2 --boot c` | 不挂 ISO，从盘启动 | 检查点 4 / 5 / 6 |

`installer` 是**为安装器测试设计**的那一条，比手工 `qemu --disk` 少三件事要记：
建盘（缺了自动建，`--size` 定虚拟大小）、挂盘、串口日志（默认 `--serial file`）。

```bash
sudo ./scripts/mipl.sh installer                       # 全套默认
sudo ./scripts/mipl.sh installer --serial console      # 串口换成可交互 socket（见 §4）
sudo ./scripts/mipl.sh installer --boot c              # 从盘启动验安装结果
sudo ./scripts/mipl.sh installer --disk mine.qcow2 --size 40G   # 换盘名/大小
```

**⚠️ 与 `qemu` 的一处已知差异**：`installer` 在 `mipl.sh:906` 写死 `--vga virtio`，
而 `qemu` 不传 `--vga`（用 QEMU 默认 std/bochs）。`mipl.sh --help` 里那句
「`-vga virtio`（cage KMS，**std VGA 起不来**）」与实测**表面矛盾**（实测出窗口的那次走的是 std），
但那次同时换了刚重建的 ISO，两个变量一起变了，**所以这条差异还没分离干净**，
见 [archive §六](../../archive/2026-09-23-kiosk启动链的两个坑.md) 与 Issue #53。跑之前先知道自己用的是哪张卡。

### 2.1 ⚠️ 要跑验收测试，就加 `--serial console`

**`--serial file` 是默认档，它只写日志、不给 shell。** 而 kiosk 会占满 tty1 ——
等你发现敲不了命令时，这一轮已经起错档了。**要边跑边敲，起 VM 时就把档换掉：**

```bash
sudo ./scripts/mipl.sh installer --serial console
# 脚本随后会打印它自己在用的那条命令，照抄即可：
socat -,raw,echo=0,escape=0x0f UNIX-CONNECT:out/installer-serial.sock
```

连过去就是**串口上的 root shell**（cmdline 里有 `console=ttyS0,115200`，串口上有 getty），
**完全不占 tty1**，`Ctrl-]` 退出。四种进出 Live 的办法见 §3.0。

## 3. 六个检查点：逐步怎么跑

检查点的定义与判据在 [05-测试方法](../../knowledge/05-测试方法.md) 第 5 节，这里只写**动作**。

### 3.0 先解决「窗口占满屏幕，我敲不了命令」

**这是设计如此，不是故障** —— kiosk 的全部意义就是占满 tty1。所以 Live 里的命令得另找地方敲。
四种办法，按推荐顺序：

| 办法 | 怎么做 | 代价 |
|---|---|---|
| **加 `--serial console`** | 起 VM 时就用它，然后 `socat` 连 socket（§2.1） | 需要**起 VM 前**决定；最适合跑验收测试 |
| **切到 tty2** | 经 QEMU monitor 发按键（见下），登录 `root`（**密码直接回车**，Live 的 root 是空密码） | 每次开机都要切一次；切回来要再发一次按键 |
| **无头 + monitor 截屏** | 见 [02-构建与QEMU测试](02-构建与QEMU测试.md) §C.3 | 看不到交互，适合 CI |
| **`systemctl stop mipl-installer`** | 在 tty2 / 串口上停掉它，拿回带日志的 tty1 | 会失去「窗口在跑」的现场 |

**切 tty 得走 monitor —— 直接按 `Ctrl+Alt+F2` 不生效**（实测）：

```text
① 窗口里按 Ctrl+Alt+2     → 进 QEMU monitor（提示符变成 (qemu)）
② 输入 sendkey ctrl-alt-f2 → 客机切到 tty2
③ 输入 sendkey ctrl-alt-f1 → 客机切回 tty1（装器界面还在）
④ 按 Ctrl+Alt+1           → 从 monitor 回到图形窗口
```

`Ctrl+Alt+<F 键>` 会被 QEMU 自己截走（那是它的 host 抓键组合），所以得让它**代发**按键。
登录 tty2 时输 `root`，密码直接回车。

> **别用 `kill` 让窗口消失**：unit 挂着 `Restart=on-failure` + `RestartSec=3`，
> 杀了 3–5 秒后会被拉起来。要它停就用 `systemctl stop`。

**为什么切 tty 就能进去**：unit 里只有 `Conflicts=getty@tty1.service`，**没碰 tty2**，
所以 tty2..N 上的 getty 一直活着。`getty@tty1` 那份 autologin 是**兜底**（安装器挂了或被 stop 掉时，
tty1 还能拿回来敲命令）—— 见 §1.3。

### 第 1 步 · 检查点 1：ISO 能进 Live

```bash
sudo ./scripts/mipl.sh build          # 产物落 out/miplinux-<日期>-x86_64.iso
sudo ./scripts/mipl.sh qemu           # 不挂盘，只看 Live
```

看到 `root@archiso ~ #`（tty1）或串口上的 `archiso login:` 就算过。

> **`qemu` 和 `installer` 都会拉起同一个 kiosk unit，所以两者都占 tty1** ——
> 「不挂盘」不等于「不会有窗口」。要纯看 Live，用 §3.0 里的办法进到别的 tty。

### 第 2 步 · 检查点 2：**安装器窗口自己出现**

```bash
sudo ./scripts/mipl.sh installer      # 或上面的 qemu；installer 会多挂一块盘
```

**判据是「不碰键盘就出窗口」。** 需要切 tty、登录、手敲命令才出来的，**不算过**
（这正是 #51 那个坑的表现，成因见 §1.2）。

没出来时，先在 Live 里看（进 Live 的办法见 §3.0）：

```bash
systemctl status mipl-installer --no-pager
journalctl -u mipl-installer -b --no-pager
```

> **`journalctl` 比串口重要**：unit 写的是 `StandardOutput=journal` / `StandardError=journal`，
> 所以 `cage` / Qt / `libseat` 的抱怨**一个都不进串口**。只看串口会误判成「什么都没发生」——
> 串口那边只有一句绿色的 `[ OK ] Started MipLinux 安装器界面.`。

### 第 3 步 · 兜底还通不通（检查点 2 的另一半）

**注意：这一步必须在 tty2 或串口上做** —— 要在 tty1 上看结果，窗口本来就在那儿占着（§3.0）。

```bash
systemctl stop mipl-installer      # 期望：tty1 落回 root@archiso ~ #
systemctl start getty@tty1         # 期望：确认回归路径可用（跑完可用 start mipl-installer 还原）
```

这一条验的是「安装器挂了人还能进去救」——Live 是唯一的维护入口，它不通等于把用户关在门外。

> 用 `stop` 而不是 `kill`：`kill` 只发信号，unit 的 `Restart=on-failure` 会在 3–5 秒后
> 把它拉起来，tty1 又被抢走 —— 那时你会以为「兜底坏了」，其实是没停干净。

### 第 4 步 · 检查点 3：界面能用（认盘 + 联网）

m0 阶段界面还是占位窗口，所以这一步目前只验**环境**：

```bash
lsblk                       # 目标盘应是 /dev/vda（virtio）
ping -c1 archlinux.org      # 或 nmcli 看连接状态
```

### 第 5 步 · 检查点 4：**从盘重启，系统能启动**

```bash
sudo ./scripts/mipl.sh installer --boot c
```

**这是最关键、最常被跳过的一条。** 盘上没引导项时脚本会明确报 `no bootable device`，
不会悄悄回到 Live。

### 第 6 步 · 检查点 5 / 6：装后系统内部

```bash
# 静态：不开机直接翻盘（比开机快一个数量级）
guestmount -a out/target.qcow2 -i /mnt && cat /mnt/etc/fstab && guestunmount /mnt

# 动态：装后系统里
cat /sys/module/nvidia_drm/parameters/modeset     # 期望 Y
pacman -Syu                                        # 检查点 6：滚动升级
```

装后系统的完整清单见 [05-装后系统验证](05-装后系统验证.md)。**真机那半段**（N 卡、桌面、中文输入法）
归那里的 §2，不在 QEMU 里做。

## 4. 日志与现场：三种拿法

### 4.1 串口日志（`--serial file`，installer 的默认）

落 `out/installer-serial.log`。**注意 unit 的输出不进这里**，它只收内核与 systemd 的消息。
`mipl.sh qemu` **不带 `--serial`**，那种实例没有日志也没有 socket。

### 4.2 串口只读探活（`--serial console`）

`--serial console` 起的是 unix socket（`out/installer-serial.sock`），
所谓「可交互」只是说有客户端连上去就能收发 —— **所以它同时是一条只读探活通道**，
不用为了看日志重开一台机器：

```bash
# 只收不发：拿一段当前屏幕内容，不改客机状态
timeout 10 socat -u UNIX-CONNECT:out/installer-serial.sock -

# 交互（Ctrl-] 退出，escape=0x0f 是仓库约定）
socat -,raw,echo=0,escape=0x0f UNIX-CONNECT:out/installer-serial.sock
```

socket 属主是 root，普通用户连不上 —— 要么 `sudo`，要么这台 VM 本来就是你自己起的。

### 4.3 journal（真正有货的那一处）

```bash
journalctl -u mipl-installer -b --no-pager            # 全部
journalctl -b -u mipl-installer -o short-precise       # 带精确时间戳，判断「慢」还是「必败」用它
```

### 4.4 无显示器时（CI / 远程）

QEMU monitor 可以截屏，见 [02-构建与QEMU测试](02-构建与QEMU测试.md) §C.3。
