## 1. 工具清单

### 1.1 `archiso`

一个 Arch 软件包，提供两样东西：

| 内容 | 路径 | 作用 |
|---|---|---|
| `mkarchiso` | `/usr/bin/mkarchiso` | 真正的构建程序，一个 bash 脚本 |
| `run_archiso` | `/usr/bin/run_archiso` | 构建完直接 QEMU 启动的辅助脚本 |
| 参考 profile | `/usr/share/archiso/configs/` | `releng`（完整 Live）与 `baseline`（最小） |

**三个容易混淆的名字：**

- **`archiso`** —— 软件包
- **`mkarchiso`** —— 包里的构建脚本
- **profile** —— 你的配置目录，`releng` 是官方参考实现

### 1.2 `mkarchiso` 的完整流水线

按源码顺序：

```
1. 读 profiledef.sh                 ← 发行版身份、引导方式、压缩算法
2. 读 profile/pacman.conf
   └─ 在【宿主机】上解析 Include     ← ★ 陷阱所在，见第 3 节
3. pacstrap 一个空目录
   └─ 按 packages.x86_64 下载安装所有包
4. cp -af profile/airootfs/. → 该目录
5. 按 file_permissions 数组重设权限
6. 在该目录内运行 mkinitcpio        ← 生成 Live 环境自己的 initramfs
7. 清理（缓存、日志、machine-id）
8. mksquashfs → airootfs.sfs         ← 整个系统变成一个只读压缩包
9. xorriso → .iso                    ← 加引导器、EFI 分区，产出成品
```

**第 3 步就是「装一个完整的 Arch 系统」**，这是理解 mkarchiso 的关键。

### 1.3 `systemd-nspawn`

systemd 自带的轻量容器工具，**属于 `systemd` 包，无需额外安装**。

#### 隔离手段谱系

| 手段 | 隔离程度 | 里面是什么 | 能否装另一个发行版 |
|---|---|---|---|
| `chroot` | 极弱 | 只是换个根目录 | 能，但很脏 |
| **`systemd-nspawn`** | 中 | 一个跑着 systemd 的完整用户空间 | **能，很干净** |
| Docker / Podman | 中 | 同上，额外管镜像分层 | 能 |
| 虚拟机 | 强 | 整个内核 + 用户空间 | 能，但重 |

#### 为什么 chroot 不够

`chroot` 只换了文件的根目录，进程与宿主机共享同一内核、同一 PID 空间、同一 `/proc`。在里面跑 `pacman` 会看到宿主机的进程表，很多操作会莫名失败或污染宿主机。

`systemd-nspawn` 提供：

- 独立的 PID / 挂载 / 网络 / UTS 命名空间
- 容器内运行自己的 systemd 作为 1 号进程
- 独立的 `/proc`、`/sys`、`/dev`

它**就是 systemd 项目自己的 chroot 替代品**，也是 Arch Wiki 推荐的从零安装方式之一。

#### 建立构建环境

```bash
# 1. 下载 Arch bootstrap（官方源约 120 MB）
curl -LO https://geo.mirror.pkgbuild.com/iso/latest/archlinux-bootstrap-x86_64.tar.zst
# 国内可用清华源：
# curl -LO https://mirrors.tuna.tsinghua.edu.cn/archlinux/iso/latest/archlinux-bootstrap-x86_64.tar.zst

# 2. 解压
sudo mkdir -p /var/lib/machines/archbuild
sudo tar --numeric-owner -xpf archlinux-bootstrap-x86_64.tar.zst \
     -C /var/lib/machines/archbuild --strip-components=1

# 3. 进入（注意：不要加 -b，原因见下方说明）
sudo systemd-nspawn -D /var/lib/machines/archbuild -u root

# 4. 容器内初始化并安装 archiso
#    pacman-key --init && pacman-key --populate archlinux
#    pacman -S archiso
```

> **不要加 `-b`。** bootstrap 的 `/etc/shadow` 中 root 是 `root:*:...`，`*` 表示没有有效密码，加了 `-b` 会停在 `archbuild login:` 且任何输入都不被接受。
>
> 构建也不需要容器内有 init 在跑——`mkarchiso` 是普通脚本，直接执行即可。详见 [work/tech/01-容器环境搭建.md](../work/tech/01-容器环境搭建.md) 步骤 3。

此后每次构建用 `machinectl start archbuild` 进入即可。

#### nspawn 与 Docker 的取舍

| | systemd-nspawn | Docker |
|---|---|---|
| 安装 | systemd 自带 | 需单独安装 |
| 操作对象 | 直接是一个目录，可直观查看改动 | 镜像分层，需 `commit` 才持久 |
| 生态 | 无 | CI 集成成熟 |

**推荐 nspawn**：因为它直接操作目录，调试构建环境时更直观，也更容易被构建脚本自动化重建。

### 1.4 QEMU / KVM

测试环境。**必须在宿主机上运行，不能在 nspawn 里运行**（原因见 [01-概念模型.md](01-概念模型.md) 第 4 节）。

需要 `edk2-ovmf` 提供 UEFI 固件：

```bash
sudo pacman -S edk2-ovmf qemu-desktop
# Fedora 对应：sudo dnf install edk2-ovmf qemu-kvm
```

### 1.6 `archiso` 的完整依赖

实测 `archiso 90-1` 的依赖（安装它会自动带入下列全部）：

**必需依赖：**

```

bash
dosfstools              提供 mkfs.vfat（EFI 分区）

```

**可选依赖（按需）：**

| 包 | 用途 | 本项目是否需要 |
|---|---|---|
| `edk2-ovmf` | `run_archiso` 模拟 UEFI | ✅ 需要（测试） |
| `qemu-desktop` | `run_archiso` | ✅ 需要（测试） |
| `grub` | ISO 内支持 GRUB 引导 | 视 `bootmodes` 而定 |
| `gnupg` | PXE 场景的 OpenPGP 校验 | ❌ |
| `openssl` | PXE 场景的 CMS 校验 | ❌ |

**结论：在 nspawn 容器内只需 `pacman -S archiso`**，构建工具链即完整。测试用的 `edk2-ovmf` 和 `qemu-desktop` 装在**宿主机**上。

## 3. 必须知道的陷阱

### 3.1 `Include` 会在宿主机上解析

**这是本项目最容易踩、且完全静默的坑。**

`mkarchiso` 的 `_make_pacman_conf()` 函数逻辑：

```bash
pacman-conf --config "${pacman_conf}" | sed ...
```

`pacman-conf` **在宿主机上执行**。而 profile 的 `pacman.conf` 中写的是：

```ini
[core]
Include = /etc/pacman.d/mirrorlist
[extra]
Include = /etc/pacman.d/mirrorlist
```

这个 `Include` 指向的是**宿主机文件系统**的 `/etc/pacman.d/mirrorlist`。

**后果：在 CachyOS 上构建，ISO 就是从 CachyOS 的源拉包做出来的。** 构建过程不会报任何错。

**两种解法：**

1. **构建放进纯 Arch 容器**（推荐）
2. **profile 中不使用 `Include`，直接写 `Server =` 行**

对本项目而言，方案 2 是迟早要做的——因为要把默认源换成国内镜像。现在顺手做掉，一举两得。

### 3.2 权限不会被保留

`_make_custom_airootfs()` 使用：

```bash
_unshare cp -af --no-preserve=ownership,mode -- "${profile}/airootfs/." "${pacstrap_dir}"
```

即**复制时故意不保留属主和权限**，之后按 `profiledef.sh` 中的 `file_permissions` 数组逐个重设。

**后果：** 任何放进 `airootfs/` 的文件，如果没在 `file_permissions` 里声明，权限就是默认值。安装器的可执行文件、需要特定读取权限的配置，都会栽在这里。

### 3.3 releng 的包清单里什么都没有

实测 releng 的 129 个包中，以下全部**不存在**：

```
nvidia / nvidia-open  ✗       fcitx5           ✗
noto-fonts-cjk        ✗       wqy 系列字体     ✗
networkmanager        ✗       pipewire         ✗
archinstall           ✓  ← 唯一现成的安装器相关组件
```

默认 ISO 是一个**命令行救援盘**，连图形界面都没有。这不是缺陷，是设计 ——
但对本项目意味着**要加的东西全是净增量**。
