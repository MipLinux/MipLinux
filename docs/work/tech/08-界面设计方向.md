## 2. 五条设计原则（每条都带判据）

| # | 原则 | 判据（看到什么算违反） |
|---|---|---|
| **P1** | **一屏一个主动作**。任何一屏只有一个 filled 按钮承担「前进 / 开始安装」 | 一屏出现两个同等视觉权重的实心按钮 |
| **P2** | **状态永远可见**。这是有副作用的操作：当前步骤、已完成步骤、目标盘、进度必须常驻可见，不能只靠转场动画表达 | 用户需要回忆「我选的是哪块盘」 |
| **P3** | **不可逆的操作二段式**。清盘 / 写引导 / 开始安装必须先出确认对话框，且用 `error` 角色而不是 `primary` | 点一下就把分区表写了 |
| **P4** | **桌面密度，不用手机档**。鼠标键盘精确输入，控件高度用桌面档；点击目标仍不小于 48×48dp | 控件高度照搬 Material 手机默认（56dp 大按钮满屏） |
| **P5** | **首帧不做动效、不做模糊，且主题必须在首帧之前定下来**。动效只在第一帧之后发生，且必须可整体关闭 | 首帧里出现动画或 backdrop blur；或者先按亮色画一帧、再跳成暗色（闪一下） |

这五条的优先级高于任何单页的视觉偏好：**冲突时按编号小的赢**。

## 3. 设计 token

取值来源：Material Web 的官方 token 产物 `v0.192`（`Platform: Web` / `Scheme: Dynamic`），逐项链接见 §9。
**token 名保持官方原名**，只加一层 `Mipl` 前缀（如 `Mipl.color.surfaceContainerHigh`），
这样与上游对照、与 Caelestia 对齐都只靠改名。

### 3.1 颜色

**种子色已定：`#2576E9`** —— 取自 [MipLinuxLogo.png](/home/neo/Pictures/Pictures/MipLinuxLogo.png) 的圆形主填充（logo 里占比最大的单一颜色）。
色板已用官方算法离线生成，**35 个角色的 dark / light 全部取值见 [附录 A](#附录-a品牌种子色与生成结果本机实测)**。

**角色清单（35 个核心角色）**，分 8 组：

| 组 | 角色 |
|---|---|
| 主色 | `primary` `on-primary` `primary-container` `on-primary-container` |
| 次色 | `secondary` `on-secondary` `secondary-container` `on-secondary-container` |
| 三色 | `tertiary` `on-tertiary` `tertiary-container` `on-tertiary-container` |
| 错误 | `error` `on-error` `error-container` `on-error-container` |
| 表面 | `surface` `surface-dim` `surface-bright` `on-surface` `surface-variant` `on-surface-variant` |
| 表面容器 | `surface-container-lowest` `surface-container-low` `surface-container` `surface-container-high` `surface-container-highest` |
| 描边 / 覆盖 | `outline` `outline-variant` `scrim` `shadow` `surface-tint` |
| 反色 | `inverse-surface` `inverse-on-surface` `inverse-primary` |

另有 `*-fixed` / `*-fixed-dim` / `on-*-fixed(-variant)` 共 12 个固定角色（壁纸变化时不跟着变），
安装器**不用**它们 —— 安装器没有动态取色，用不上这层稳定性保证。

**方案选择：`SchemeTonalSpot`**（Android 的默认动态方案），不用 `SchemeContent`。
理由：安装器是**品牌**界面而不是内容界面，tonal spot 对种子色的色相、彩度保留更克制，浅色模式下不会出现高彩度的容器色。
两方案的差异实测很小（`primary-container` 在 dark 下 `#2b4678` vs `#3c93fb`），要改也只是换一个构造函数参数。

**对比度档：`contrastLevel = 0`（标准）。** 高对比度方案**不做**（维护者 2026-10-01 决定），
理由与边界见 §4.2 —— 色板一旦按 `contrastLevel ≠ 0` 重生成，全部取值都要换一套，这是另一个方向的工。

**运行期纪律**：色板在**设计阶段**离线生成（本次已完成），**构建期零依赖、运行期零计算**。
不要为了「以后能换主题」而在安装器里塞 HCT 取色或图像量化 —— 那是 P5 要拦的开销。

**判据**：正文文本与背景对比度 ≥ 4.5:1；大字（≥24px 或 ≥18.66px 且 700 字重）与图标 ≥ 3:1。
对比度用脚本断言，不靠眼睛 —— 本次已在设计阶段跑通，结果见附录 A。

### 3.2 字形（15 档）

官方 `plain` 与 `brand` 都是 **Roboto**、字重只有 400 / 500 / 700。
但 Live 里没有 Roboto，所以家族映射改为：

| 用途 | 家族 | 理由 |
|---|---|---|
| 拉丁 | `Noto Sans` | 与中文同源、字面一致 |
| 中文 | `Noto Sans CJK SC` | 已在 `noto-fonts-cjk` 内 |
| 等宽（路径、UUID、命令输出） | `Noto Sans Mono` | 同一包内的等宽，避免再引字体 |

> ✅ **已核实（依据官方包内容清单，非本机实测）**：`noto-fonts` 的字重是**静态档位，不是变量字体** ——
> `NotoSans-Regular / -Medium / -Bold / -Light / -Thin / -Black` 都在，`noto-fonts-cjk` 同样带 `NotoSansCJK-Medium.ttc`。
> 所以上表 `label-*` / `title-*` 的 **500 是真实字重**，不需要合成粗体
> （Qt 的 synthetic bold 会与 CJK 回退叠加，字形发糊）。落地第一步仍建议在 ISO 里用 `fc-list` 复核一次族名。
>
> 包清单既然可追加，也可以为了「字面上就是 MD3」而加 `ttf-roboto`。**不推荐**：Roboto 不含 CJK，
> 中文照样要回退到 Noto；而 `noto-fonts` **一个包就有 630 个文件**，再加一份字体只会让 fontconfig 的首扫更贵 ——
> 首扫正是 §1 首帧预算里那笔钱。装后系统的 `GoogleSansFlex` 是上游自带资产（不在仓库里），也不适合为安装器单独引入。

字号（官方 rem 已换算成 px，1rem = 16px）：

| 角色 | 字号 | 行高 | 字距 | 字重 |
|---|---|---|---|---|
| `display-large` | 57 | 64 | −0.25 | 400 |
| `display-medium` | 45 | 52 | 0 | 400 |
| `display-small` | 36 | 44 | 0 | 400 |
| `headline-large` | 32 | 40 | 0 | 400 |
| `headline-medium` | 28 | 36 | 0 | 400 |
| `headline-small` | 24 | 32 | 0 | 400 |
| `title-large` | 22 | 28 | 0 | 400 |
| `title-medium` | 16 | 24 | 0.15 | 500 |
| `title-small` | 14 | 20 | 0.10 | 500 |
| `body-large` | 16 | 24 | 0.50 | 400 |
| `body-medium` | 14 | 20 | 0.25 | 400 |
| `body-small` | 12 | 16 | 0.40 | 400 |
| `label-large` | 14 | 20 | 0.10 | 500 |
| `label-medium` | 12 | 16 | 0.50 | 500 |
| `label-small` | 11 | 16 | 0.50 | 500 |

**用在安装器的哪几档**：`display-*` 只用于欢迎 / 完成页的标题；页面标题用 `headline-small`；
区块标题 `title-medium`；正文 `body-medium`；说明 / 次要文字 `body-small`；按钮与标签 `label-large`。
**其余 8 档定义但不使用** —— 定义齐是为了与上游对照时能逐项对上。

**CJK 追加规则（MD3 未覆盖，本文件补）**：中文没有词间空格，官方那套拉丁字距直接套会偏散，
所以中文串一律把 tracking 归零；行高沿用官方值。
文案不许截断按钮：按钮宽度按文案自适应，长文案换行而不是省略号。

| token | 值 (px) | 安装器分配 |
|---|---|---|
| `corner-none` | 0 | 全宽分隔区、进度条底槽 |
| `corner-extra-small` | 4 | 输入框（filled / outlined） |
| `corner-small` | 8 | chip、tooltip |

### 3.4 间距与网格

基准 **4px 网格**，安装器只用 6 档：`4 / 8 / 12 / 16 / 24 / 32`，另加页面级 `48`。

| 用途 | 值 |
|---|---|
| 图标与文字之间 | 8 |
| 控件内部左右内边距 | 16 |
| 同一区块内元素间距 | 12 |
| 区块之间 | 24 |
| 页面左右安全边距（桌面档） | 32，窄窗口降到 16 |
| 底部动作区上边距 | 24 |

对齐 Caelestia 的 `spacing.scale` / `padding.scale`：**同一套档位、同一个 scale 语义**，
这样以后要整体「紧凑 / 宽松」只需改一个倍数。

### 3.5 高度与状态层

官方高度是 web 的阴影档位：`level0=0 / level1=1 / level2=3 / level3=6 / level4=8 / level5=12`。

**安装器的取舍：不用阴影，用层级 + 描边。** 理由有两条，都与本项目直接相关：

1. 阴影在 kiosk 上是额外的合成开销（cage 这条链按既有记录走软件渲染，见 §0.1），落进 P5 的首帧预算里不划算；
2. 深色底上阴影几乎不可见，靠 `surface-container-*` 的层级差 + `outline-variant` 描边更清晰、更省。

因此：主内容面板 `surface-container-lowest`、卡片 `surface-container`、对话框 `surface-container-high`，
一律配 1px `outline-variant`。**阴影只在「浮层确实需要脱离层级」时用**（如菜单），且只到 level2。

状态层（叠加在控件底色上，官方 v0.192 取值）：

| 状态 | 不透明度 |
|---|---|
| hover | 0.08 |
| focus | 0.12 |
| pressed | 0.12 |
| dragged | 0.16 |

> 本稿曾写过「部分旧版规范写 focus / pressed 各 0.10」。**该说法找不到可引用的权威源，已删除** ——
> 复核时查了 material-web 的前代 token 版本（v0.172 同样是 0.12）与 MDC Web 的 ripple 主题（另是 0.08 / 0.24 / 0.16），
> 都不含 0.10。**此处只认 0.12**，不接受两个数并存；要改先拿出可引用的源。

|---|---|---|---|

| `short2` | 100 | `medium2` | 300 |

缓动（cubic-bezier）：

| token | 值 |
|---|---|
| `easing-standard` / `easing-emphasized` | `(0.2, 0, 0, 1)` |
| `easing-standard-accelerate` | `(0.3, 0, 1, 1)` |
| `easing-standard-decelerate` | `(0, 0, 0, 1)` |
| `easing-emphasized-accelerate` | `(0.3, 0, 0.8, 0.15)` |
| `easing-emphasized-decelerate` | `(0.05, 0.7, 0.1, 1)` |
| `easing-linear` | `(0, 0, 1, 1)` |

**安装器的使用纪律**：

- 只用 `short*` 与 `medium*` 两档；`long*` / `extra-long*` 只定义不使用（安装等待页的循环动效除外）。
- QML 映射：`easing.type: Easing.Bezier; easing.bezierCurve: [0.2, 0, 0, 1]`（四个数即 x1, y1, x2, y2）。
- **首帧零动效**：首屏不得挂动画；进度条的循环动效必须在第一帧之后启动。
- 所有时长乘一个全局 `motion.scale`；为 0 时代表「关闭动效」（无障碍设置 / 低配机）。

### 3.7 图标

字形集：**Material Symbols**（Apache-2.0）。两条交付方式：

| 方式 | 代价 | 结论 |
|---|---|---|
| **SVG 资源**随安装器打包（`qt6-svg` 已在清单） | 要自己挑、自己打包所需字形 | **推荐**：不碰 fontconfig，不占首帧预算 |
| 追加 `ttf-material-symbols-variable`（`extra`，装后 33MB） | 一份新的字体元数据进 ISO，喂给 fontconfig 首扫 | 若要与 Caelestia 的图标字体完全同源再考虑；**要单独过批准** |

- 尺寸档对齐 Caelestia 的 icon 档：`15 / 18 / 24 / 36`。
- 风格只用一套（默认 `Outlined`），**不混用** rounded / sharp。
- 图标必须配文字标签或 tooltip；只有图标按钮限 `24px` 档，且必须可聚焦。

### 3.8 窗口尺寸类

MD3 的五档：`compact <600` / `medium 600–839` / `expanded 840–1199` / `large 1200–1599` / `extra-large ≥1600`。

**安装器只实现两档版式**：

| 版式 | 触发 | 布局 |
|---|---|---|
| 单列 | `compact` / `medium` | 标题 + 内容 + 底部动作区，垂直流 |
| 双列 | `expanded` 及以上 | 左侧步骤导航（纵向列表，**不是** MD3 navigation rail）+ 右侧内容 + 底部动作区 |

理由：kiosk 的分辨率是可枚举的，多一档版式就多一套要维护、要测的东西；等出现真实设备再补。

**键盘（与 P4 配套）**：全流程 Tab 可达；焦点环 = 2px `primary` 外描边；`Enter` 触发主动作；
`Esc` 只做返回，**永不**触发破坏性动作。焦点顺序与视觉顺序一致 —— 这条会进 V3 的验收。

### 3.9 主题模式：亮 / 暗 / 跟随时间

需求（维护者 2026-10-01）：**两套都要做；按时间自动切换；同时给一个按钮手动切换。**

| 项 | 决定 |
|---|---|
| 默认 | `auto`（跟随时间） |
| 自动规则 | 本地时间 **07:00–18:59 → 亮色**；**19:00–06:59 → 暗色** |
| 手动 | top app bar 上的 icon button，点一下在亮 / 暗之间切换，**并在本次会话内锁定**（不再被自动规则改回去） |
| 解析时机 | **首帧之前**（P5）；解析结果决定第一帧用哪套色板 |
| 运行期 | `auto` 模式下用一个低频定时器（建议 30s）重新求值 —— 安装要跑好几分钟，**跨过 19:00 时应当实时切换**；被手动锁定后停止求值 |
| 切换动效 | 颜色过渡 `short4`（200ms）+ `easing-standard`；**不**做遮罩淡入、不做模糊 |
| 不做 | 写盘记忆（Live 重启即失效，没有意义） |

**为什么是固定时刻而不是日出日落**：日出日落要经纬度，而装机环境可能没网、没有定位 —— 拿不到就不该假装能算。
固定区间零依赖、可预测、**是本地时间的纯函数**，所以能当单元测试测（见 V6）。
等装后系统有了网络与定位，再谈「真日落」。

**时区从哪来**：读安装器当前的时区选择；用户还没走到那一步时，用系统当前时区（Live 里通常是 UTC）。
这个近似要写进 tooltip —— **不要让用户以为它算准了**。

**手动的语义**：按钮只做「亮 ↔ 暗」两态切换，不提供「恢复自动」的入口（v0.1 边界，见 §4.2）。
tooltip 必须显示当前状态（「跟随时间」/「已手动锁定为暗色」），否则用户不知道自动还生不生效。

### 3.10 缩放与高分屏

**硬约束（§1 已列）**：cage 没有缩放选项，Qt 在 Wayland 下只读整数 `wl_output::scale`。
所以**不能指望合成器**，缩放必须在启动安装器时于应用侧施加。

| 决策 | 内容 |
|---|---|
| 只支持整数档 | `1x / 2x / 3x`。Wayland 的 `wl_output::scale` 是整数 —— 不要设计 1.25 / 1.5 这类档位 |
| 施加方式 | 启动器算好目标值并设 `QT_SCALE_FACTOR`（Qt 文档说它是给测试用的；在没有合成器配置的 kiosk 里它是唯一可用的杠杆，**这处偏离要写注释说明理由**） |
| 不用 `QT_FONT_DPI` | Qt 文档明确说非 EGLFS 平台避免用它 |
| 目标值怎么算 | ① 合成器给了 scale > 1 → **以它为准**（`scale == 1` **不算信息、不短路** —— cage 里它就恒为 1，当成终值会让高分屏停在 1x）；② 拿得到物理尺寸且 DPI ≥192 → 2x、≥288 → 3x（DPI 取**对角线**口径）；**② 的 DPI 低于 192 时继续走 ③**（维护者 2026-10-01 裁决：27" 4K 的 163 DPI 若停在 1x，与 §8.1「高分屏不得停在 1x」相抵）；③ 按分辨率兜底：宽 ≥3200 → 2x，≥5120 → 3x；④ 都没有 → 1x **并记一条日志**（不静默） |
| 手动覆盖 | `--scale=<n>`（或等价环境变量），供测试与特殊屏 |
| 断点判定 | 用**逻辑像素**（Qt 的 device-independent 像素）。4K@2x 的逻辑宽是 1920，不是 3840 |
| **禁止** | 在 QML 里手动乘 `devicePixelRatio` / `Screen.devicePixelRatio` —— Qt 已经处理过，再乘一次就是**双重缩放**。这是高分屏下最常见的自伤 |

**两层缩放（本节的关键区分）**：维护者已确认「界面里也要能自己调缩放」（2026-10-01）。

| 层 | 谁决定 | 何时生效 | 值域 |
|---|---|---|---|
| **设备层** | 启动器按面板密度 / 分辨率算 → `QT_SCALE_FACTOR` | **启动时**（Qt 初始化之前） | `1x / 2x / 3x`（整数） |
| **界面层** | 用户在界面里调 → `Mipl.scale`（我们自己的 token 倍数） | **实时生效，不用重启** | `0.85 / 1.0 / 1.15 / 1.3` |

实际观感 = 设备层 × 界面层。设备层解决「屏幕太密」，界面层解决「我看不清 / 太大了」。

**界面层为什么不复用 `QT_SCALE_FACTOR`**：那个变量在 Qt 初始化时就定死了，运行期改不了；
为改它而重启进程，在安装器里不可接受。所以界面层必须乘在**我们自己的 token** 上 ——
这恰好与 Caelestia 的 `appearance.*.scale` 是同一个语义，两端又对上一次。

**控件**：top app bar 上一个「Aa」图标按钮 → MD3 menu，四档「小 / 默认 / 大 / 更大」，当前档打勾，
切换即时生效、不写盘。菜单项要显示百分比，否则「大」到底多大没人知道。

**界面层乘什么**：字号、行高、间距、圆角、控件高度、图标尺寸 —— 全是**逻辑尺寸**；
**绝不**再乘 `devicePixelRatio`（见上表的禁止项）。图标跟着 `Mipl.scale` 走，SVG 因此不会糊（§3.7）。

**界面层不改变版式**：断点只由**屏幕逻辑宽**决定，不受 `Mipl.scale` 影响 ——
否则「把字调大」会把双列挤成单列，那是意外行为而不是特性。空间不够时靠换行与滚动解决。

**为什么「按分辨率兜底」不是可选项**：维护者已点明「高分屏不能用 1x，否则画面过小」。
而笼子里最容易拿到 1x 的恰恰是**虚拟显示**（QEMU / 无 EDID 的显示器）—— 它同时「分辨率高」又「没有物理尺寸」，
两个条件正好落进必须兜底的那一格。

**位图与矢量**：位图资产按 Qt 约定出 `logo@2x.png`（Qt 自动挑）；**SVG 不需要**，矢量在任何 DPR 下都清晰 ——
这是 §3.7 选 SVG 图标的又一条理由。

**待核实已闭环**：cage **确实**实现了基础支持 —— 2023-07-21 的提交 `6f78d9d5`（「cage: add basic wlr-output-management support」）
创建了 output manager、处理 `apply` / `test`，并应用 `scale` / `transform` / `mode` / `enabled`。
装后系统的 Hyprland 侧同样支持（[PR #12236](https://github.com/hyprwm/Hyprland/pull/12236) 修的就是 `wlr-randr` 与 monitor reload 的配合）。

**但主路径仍然是应用侧的 `QT_SCALE_FACTOR`**，两条理由：

1. 合成器侧要在 cage 会话里**先跑一个客户端**把缩放设好、再启动安装器（`wlr-randr` 不是图形程序，可以串进启动脚本），
   多一个进程与时序问题；应用侧只是启动器里加一个环境变量。
2. 协议里的 scale 是定点数，但协议原文写明合成器「might round the scale if it doesn't support fractional scaling」，
   而 Qt 文档只承诺整数 —— 档位无论如何还是 `1x / 2x / 3x`。

**顺带一条佐证**：协议规范里 `physical_size` 事件「只在输出确实有物理尺寸时才发送（比如不是投影仪或虚拟设备）」——
这正好印证了上面「虚拟显示拿不到物理尺寸、必须按分辨率兜底」的前提。

**已批准并落进清单（2026-10-01）**：`profile/packages.x86_64` 的「安装器」段已加 `wlr-randr`
（`extra`，0.5.0，MIT，装后 29KB，依赖只有 `glibc` + `wayland`）。它不是主路径，而是**应急与验证工具**：
现场卡在 1x 时人能立刻改回来，V7 也能直接观察合成器侧的缩放值。

两点边界要写清：

- **只影响 Live 侧**。按 [06 的 P10](../../knowledge/06-待定事项.md) 的现状，`profile/packages.x86_64` 是 **Live 的清单**；
  装后系统装什么由安装器的计划决定（P10 未定案）。所以这一条不会跟着进装后系统。
- **未构建验证**。改完跑过 `./scripts/check-identity.sh`（全绿），但**没有构建 ISO**，
  所以「包真的进去了、`wlr-randr` 在 cage 里真的能改缩放」都还是**未实测** —— 要等下一次构建才能记成 ✅。

## 4. 组件清单

「现成度」栏：**覆写** = Qt Quick Controls 有对应控件、换皮肤即可；**组合** = 用 QQC 现有件拼；
**自建** = Qt 没有对应件，必须从零写。「工作量」是相对量级（S/M/L），不是工时承诺。

> 「安装器用在哪」这一列是**示例映射**：页面清单与字段范围以既有界面工作文档为准（见 §0.1 的污染披露），
> 本文只负责回答「这些场景该用哪个 MD3 组件」。

### 4.1 要做的

| MD3 组件 | 变体 | 安装器用在哪 | 现成度 | 工作量 |
|---|---|---|---|---|
| Button | filled / tonal / outlined / text | 前进、返回、次动作 | 覆写 | M |
| Icon button | standard / filled | 返回、帮助、主题切换（§3.9）、缩放「Aa」（§3.10） | 覆写 | S |
| Dialog | basic | 不可逆操作确认（P3） | 覆写 | M |
| Linear progress indicator | determinate / indeterminate | 安装进度、步骤进度 | 覆写 | S |
| Text field | filled / outlined | 主机名、用户名、密码 | 覆写 | M |
| Switch | — | 布尔选项 | 覆写 | S |
| Checkbox / Radio | — | 少量互斥选择 | 覆写 | S |
| List item | 1–3 行 | 磁盘、语言、时区、键盘候选 | 覆写 | M |
| Card | outlined / filled | 列表项容器、摘要块 | 组合 | S |
| Top app bar | small | 页面标题 + 返回 | 自建 | M |
| Segmented button | — | 2–3 项互斥切换（如语言） | 自建 | M |
| Chip | filter | 可多选的标签式筛选 | 自建 | M |
| Snackbar | — | 非阻塞错误 / 提示 | 自建 | M |
| Tooltip | plain | 图标按钮的说明 | 覆写 | S |
| Menu | — | 下拉选择（替代自造选择器）、缩放档位菜单 | 覆写 | S |
| Divider | full-width / inset | 分组分隔 | 组合 | S |
| Badge | small | 数量提示 | 自建 | S |

> 「步骤指示」没有单独一行：**MD3 没有 stepper 组件**，不要自造一个非 MD3 的控件。
> 步骤感由 `Linear progress + 「第 N / M 步」文字`表达 —— 这既是 MD3 合规做法，也正中 P2。

### 4.2 明确不做的

`bottom sheet` · `side sheet` · `navigation rail` · `navigation drawer` · `FAB` · `carousel` ·
`date picker` · `time picker` · `search bar` · `data table` · `slider` · `tabs` · `bottom app bar` ·
主题三态菜单（恢复自动） · 高对比度方案（`contrastLevel` ≠ 0）

理由：要么安装器的交互里没有对应场景，要么引入后要多维护一整套状态与无障碍语义。
最后两项是**本轮明确砍掉**的：「恢复自动」需要第三态 UI 与一套状态显示规则，而一个按钮已经满足需求；
高对比度方案等于再生成一整套色板，是另一个方向的工作量。
**这一节是边界，改它要单独讨论，不能顺手加。**

## 5. 两条实现路线

| | 路线 A：Qt Material style 当底座 | 路线 B：Qt Basic style 当底座 + 自建 MD3 层 |
|---|---|---|
| 做法 | `import QtQuick.Controls.Material`，覆写 `Material.primary/accent/background/foreground` | `import QtQuick.Controls.Basic`，自建 token 单例 + §4.1 的组件层 |
| 现成得到什么 | 控件的布局、ripple、焦点、无障碍语义 | 控件的布局、焦点、无障碍语义（Basic 是「完整但无皮肤」，**ripple 要自己写**） |
| **颜色** | 可写的附加属性一共 8 个：`theme` / `primary` / `accent` / `foreground` / `background` / `elevation` / `roundedScale` / `containerStyle` —— **拿不到 `surface-container-*` / `outline` / 状态层** | 35 个角色全部可控 |
| **字形** | 由 style 内部决定，只能整体换字体，拿不到 15 档角色 | 15 档全部可控 |
| **形状** | Qt 6.5+ 有 `roundedScale`（7 档，与 MD3 同构）—— 这条 A 反而省事 | 要自己写，但值与档位和 MD3 一致 |
| 结果 | 「M3 的外壳、M2 的内芯」：深色层级、描边、状态层都做不出来 | 与 MD3 token 逐项对得上 |
| 代价 | 省 2–3 个组件的工作量 | 多写 §4.1 那 17 项（自算工作量：**M 8 项 / S 9 项 / 自建 5 项**） |
| 风险 | 越往后越要在 style 内部打补丁，补丁不跟着 token 走 | 无障碍语义要自己保证（Basic 不白送观感，但保住了 `Accessible` 属性） |

**推荐路线 B。** 三条理由：A 缺的恰好是本方向的核心（层级、描边、状态层、字形角色）；
安装器要的组件只有 17 项、且**都是简单件**（没有一个需要复杂手势或虚拟化）；
token 一旦自持，就能原样导出给 Caelestia 侧对齐（§6 阶段 3）。

> 关于「密集档」：`Material.variant`（Normal / Dense）**不是附加属性**，是全局配置
> （`qtquickcontrols2.conf` 的 `Variant=` 或环境变量 `QT_QUICK_CONTROLS_MATERIAL_VARIANT`）——
> Qt 头文件里它的枚举在，但**没有对应的 `Q_PROPERTY`**，QML 里不能按控件设置。
> 所以路线 A 连「按页切换密度」都做不到。这一点复核时有过分歧，以
> [`qquickmaterialstyle_p.h`](https://github.com/qt/qtdeclarative/blob/6.11/src/quickcontrols/material/qquickmaterialstyle_p.h) 为准。

**A 仍有一个用途**：作为**对照实现**保留一个最小样例，用来验证 Basic 版自建件的行为（焦点、ripple、键盘）没有退步。这不是第二套产品，是测试夹具。

### A.1 种子色怎么定的

1. 从 [MipLinuxLogo.png](/home/neo/Pictures/Pictures/MipLinuxLogo.png)（1254×1254）里按面积统计主色，得到 logo 的圆形主填充是蓝色系，占比最大的单一颜色为 **`#2576E9`**（约 7.2% 面积）。
2. 用官方流水线（`QuantizerCelebi` + `Score`）对同一张图独立取色，首选为 `#3C93FB` —— 与上一步只差一个色阶。
   > 注意：`QuantizerCelebi` 内部是 Wu + WSMeans，**WSMeans 的初始化带随机性**，这个「首选」在两次运行间会差 ±1 阶

### A.4 复现方式

这套命令只用于**设计阶段生成色板**，与 ISO 构建过程无关，不进任何包清单。

```bash
# 1) 官方算法库（0.4.0 的 ESM 产物有打包缺陷，Node 直接 import 会 ERR_MODULE_NOT_FOUND，用 0.3.0）
mkdir -p /tmp/mip-md3 && cd /tmp/mip-md3 && npm init -y
npm install @material/material-color-utilities@0.3.0

# 2) 从 logo 提取像素：剔掉透明与纯白，留 128×128 的 ARGB 整数
python3 - <<'PY'
import json
from PIL import Image
im = Image.open('/home/neo/Pictures/Pictures/MipLinuxLogo.png').convert('RGBA').resize((128, 128))
px = [(a << 24) | (r << 16) | (g << 8) | b
      for r, g, b, a in im.get_flattened_data()
      if a >= 200 and min(r, g, b) <= 245]
json.dump(px, open('/tmp/mip-md3/pixels.json', 'w'))
print(len(px), '像素参与取色')
PY
```

```js
// 3) gen.mjs —— 生成 35 个角色并断言对比度
import fs from 'fs';
import { QuantizerCelebi, Score, Hct, argbFromHex, hexFromArgb, SchemeTonalSpot, Contrast }
  from '@material/material-color-utilities';

const px = JSON.parse(fs.readFileSync('/tmp/mip-md3/pixels.json', 'utf8'));
console.log('官方打分候选:', Score.score(QuantizerCelebi.quantize(px, 128), 8).map(hexFromArgb));

const SEED = process.argv[2] ?? '#2576E9';            // A.1 选定的品牌种子
const ROLES = ['primary','onPrimary','primaryContainer','onPrimaryContainer',
  'secondary','onSecondary','secondaryContainer','onSecondaryContainer',
  'tertiary','onTertiary','tertiaryContainer','onTertiaryContainer',
  'error','onError','errorContainer','onErrorContainer',
  'surface','onSurface','surfaceVariant','onSurfaceVariant','surfaceDim','surfaceBright',
  'surfaceContainerLowest','surfaceContainerLow','surfaceContainer','surfaceContainerHigh',
  'surfaceContainerHighest','outline','outlineVariant','scrim','shadow','surfaceTint',
  'inverseSurface','inverseOnSurface','inversePrimary'];

const schemes = {};
for (const dark of [true, false]) {
  const s = new SchemeTonalSpot(Hct.fromInt(argbFromHex(SEED)), dark, 0.0); // contrastLevel 0
  schemes[dark ? 'dark' : 'light'] = Object.fromEntries(ROLES.map(r => [r, hexFromArgb(s[r])]));
}
fs.writeFileSync('/tmp/mip-md3/final.json', JSON.stringify({ seed: SEED, schemes }, null, 2));

// 对比度：Material 保证 4.5:1 用的就是 Contrast.ratioOfTones
const tone = (hex) => Hct.fromInt(argbFromHex(hex)).tone;
const PAIRS = [['onSurface','surface',4.5], ['onSurface','surfaceContainer',4.5],
  ['onSurface','surfaceContainerHighest',4.5],
  ['onSurfaceVariant','surfaceContainer',4.5], ['onPrimary','primary',4.5],
  ['onPrimaryContainer','primaryContainer',4.5], ['onSecondaryContainer','secondaryContainer',4.5],
  ['onTertiaryContainer','tertiaryContainer',4.5], ['onError','error',4.5],
  ['onErrorContainer','errorContainer',4.5], ['inverseOnSurface','inverseSurface',4.5],
  ['outline','surface',3.0], ['primary','surface',3.0], ['error','surface',3.0]];
let bad = 0;
for (const mode of ['dark', 'light']) {
  const s = schemes[mode];
  for (const [fg, bg, min] of PAIRS) {
    const r = Contrast.ratioOfTones(tone(s[fg]), tone(s[bg]));
    if (r < min) { bad++; console.log(`❌ ${mode} ${fg}/${bg} = ${r.toFixed(2)} < ${min}`); }
  }
}
console.log(bad === 0 ? '✅ 全部通过' : `${bad} 组不合格`);
```


> 环境：Node v24.19.0 + `@material/material-color-utilities` 0.3.0；像素提取用 Python 3 + Pillow 12.3.0。

> 与 A.3 的 28 条断言一致）。2026-10-01 复核时发现本机 `/tmp/mip-md3/gen.mjs` 的**派生版本**把种子写死成
> `ranked[0]`（算法打分首选 `#3c93fb`），于是同一格算出 **14.38** 而不是本表的 14.41 —— 两个数**不同源**，
