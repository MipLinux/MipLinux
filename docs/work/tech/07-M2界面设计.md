# 技术细节 07 · M2 界面设计与原型

> 目标：把 M2（Qt6 前端）的**设计语言**与**五个页面**定到可照着实现的程度，
> 并提供一套**能跑的原型**用于评审。
>
> 本文是 [installer-roadmap](../installer-roadmap.md) §4 里 M2 的设计产出。
> 线 G 的 G3 条目见 [2026-09-23.md](../2026-09-23.md)。
>
> **本文的实测状态逐条标注**（口径见 [05-测试方法](../../knowledge/05-测试方法.md) 第 1 节）：
> `✅ 已实测` = 本机真跑过；`⏳ 未实测` = 只做了静态检查，**不许省成「已验证」**。

## 1. 怎么跑原型（先看这条）

**不要用 `qmlscene` / `qml`。** 本机（CachyOS，Qt 6.11.2 + PySide6 6.11.2）实测这两个
Qt 自带工具**连纯 QML 文件都加载不了**：

```
$ qmlscene plain.qml          # plain.qml 只有 QtQuick 与 QtQuick.Window，没有任何自定义 import
file:///tmp/qmltest/plain.qml:-1 Library import requires a version
```

文件名是空的（`:-1`）—— 报错来自 Qt 工具自身的动态库加载，与 QML 内容无关。
同一个文件用 PySide6 的 `QQmlApplicationEngine` 直接加载则完全正常。
**所以本机迭代走 Python，这也正是安装器真身要用的那条路**（`mipl-installer` 本来就是 PySide6 程序）。

```bash
# 取图（默认全部页面 → out/m2-prototype/，已 gitignore）
python3 installer/frontend/tools/shots.py
python3 installer/frontend/tools/shots.py --page tokens        # 只取一页
python3 installer/frontend/tools/shots.py --list               # 看有哪些页面
python3 installer/frontend/tools/shots.py --size 1024x600      # 验小屏降级
python3 installer/frontend/tools/shots.py --out /tmp/m2-shots  # out/ 是 root 的时候用这个

# 在真实 kiosk 里看（cage 全屏）
sudo ./scripts/mipl.sh installer --serial console
```

### 1.1 取图为什么走 `offscreen`

宿主显示器在 **1.66667** 缩放下，普通窗口抓出来是**设备像素**（1280×800 的逻辑窗口抓成
2133×1333）。同一份 QML 在两台机器上会得到不同尺寸的图 —— 评审时说不清「你看的是哪一版」。
`shots.py` 因此把 `QT_QPA_PLATFORM` 钉成 `offscreen`，那里 `devicePixelRatio` 恒为 1。
出图不弹窗，也顺带避免取图期间在维护者屏幕上闪一堆窗口。

## 2. 设计语言

### 2.1 四条原则

1. **克制的仪器感** —— 要的是「可信」不是「惊艳」。擦盘会毁数据，界面不许有花活误导判断。
2. **高危信息不靠颜色传达** —— 颜色只是加强；危险必须同时有图标、文案、动作成本。
3. **中文是第一公民** —— 中文是主语言，英文跟随。中文排版（行宽、标点、字重）按原生处理。
4. **渐进披露** —— 首屏只回答「这是什么、能不能装」；日志、分区细节、错误详情一律折叠。

**视觉方向：** 浅色、大圆角、年轻化。深色「仪器盘」方案已否决 —— 理由见 §7 的排除表。

**按 2026-09-25 的评审意见调整的两条（已落地）：**

1. **LOGO 不做装饰。** 曾经在 LOGO 外面画一圈轨道环 + 一颗星光做描线动画，已去掉。
   LOGO 自己已经是一枚完整的图形（蓝色渐变圆 + 白海豹 + 山形 M + 星光），
   外面再套一层是替它说话，不是让它说话。情绪价值改由**版面留白、字体、克制的动效**给。
2. **认知负担再降一档。** 具体做法见 §3，其中账户页与完成页在评审后又压掉了
   两张卡与一处 Alert —— 目标是**一屏放得下**，不指望用户滚动。

### 2.2 颜色

**强调色分三档**，这是从 LOGO 蓝色推出来的硬约束，不是审美偏好：

| 令牌 | 值 | 用途 | 实测对比度 |
|---|---|---|---|
| `accentDecor` | `#2A78EC` | **只做装饰**：图标、进度条填充、星光、选中描边 | 对白 **4.20:1** |
| `accentAction` | `#1A5FD0` | 正文链接、填充按钮底 | 对白 **5.85:1** ✅ |
| `accentPress` | `#12489F` | 按下态、深底文字 | 白字压它 **8.56:1** ✅ |
| `accentTint` | `#EAF2FE` | 选中底、进度轨道、浅色标签底 | 装饰 |
| `accentBorder` | `#BBD3F8` | 选中态描边 | 仅装饰（1.52:1） |

> **为什么必须分档：** LOGO 主色压白只有 **4.20:1**，达不到 AA 正文的 4.5:1。
> 所以填充按钮一律用 `accentAction`。两档在 `Tokens.qml` 里**命名就分开**
> （`accentDecor` / `accentAction`），让「顺手用错」在评审里一眼可见。

| 中性 / 语义 | 值 | 用途 | 实测 |
|---|---|---|---|
| `pageBg` | `#F5F7FB` | 页面底 | — |
| `cardBg` | `#FFFFFF` | 卡片 | — |
| `subtleBg` | `#F0F3F9` | 悬停、分组底 | — |
| `border` | `#E3E8F0` | 分隔与卡片描边 | 装饰 |
| `borderField` | `#CBD4E2` | 输入框描边（比 border 深一档） | 装饰 |
| `text` | `#171B24` | 主文字 | 对底 **16.07:1** ✅ |
| `textMuted` | `#525C6B` | 次要文字 | 对白 **6.77:1** ✅ |
| `textFaint` | `#6B7787` | 提示（**只放卡片上**） | 对卡 4.55:1 ✅ / 对底 4.24:1 ⚠️ |
| `danger` / `dangerFill` | `#D32F3D` / `#C62828` | 危险文字 / 填充 | 4.95:1 / 白字 5.62:1 ✅ |
| `success` | `#1B7F45` | 成功 | 5.04:1 ✅ |
| `warning` | `#9A6400` | 警告 | 5.00:1 ✅ |
| `focusRing` | `#2A78EC` | 焦点环 | 4.20:1（UI 元件达标） ✅ |

**两处刻意的例外：**

- **底不用纯白**：kiosk 全屏纯白发亮、层次全靠描边。浅灰底 + 纯白卡既把「层」讲清楚，
  又省掉重阴影 —— QEMU 下是 `WLR_RENDERER=pixman` 软件渲染，重投影很贵。
- **`textFaint` 只能放在卡片上**：它对页面底只有 4.24:1。所以 `TokensPage.qml` 里所有
  提示文字都在白卡上，界面上也一样。

**取色依据（实测，不是目测）：**

```bash
convert MipLinuxLogo.png -colors 24 histogram:info: | sort -rn | head
#   #2A78EC（主）· #1957CB（深）· #3389F7（浅）· #B7D1F8 / #D9E6FA（最浅）
```

### 2.3 圆角（「大圆角」的具体值）

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `rControl` | 12 | 输入框、下拉、小控件 |
| `rPill` | 999 | 按钮（胶囊） |
| `rCard` | 20 | 卡片 |
| `rPanel` | 24 | 大面板、欢迎页主视觉容器 |

### 2.4 阴影：极轻

卡片 `0 1px 3px rgba(23,27,36,.06)`；抬升层 `0 8px 24px rgba(23,27,36,.10)`。
**层次主要靠描边**，阴影只是加分 —— 软件渲染下不指望它撑起层次。

### 2.5 字体

| 角色 | 字体 | 字号 / 行高 |
|---|---|---|
| 页标题 `display` | `Noto Sans CJK SC` DemiBold | 30 / 1.3 |
| 次标 `heading` | 同上 DemiBold | 20 / 1.35 |
| 正文 `body` | 同上 Regular | 16 / 1.5 |
| 辅助 `small` | 同上 Regular | 14 / 1.5 |
| 微 `micro` | 同上 Regular | 12 / 1.4 |
| **技术信息** `technical` | `Maple Mono NF CN` | 14 / 1.5 |

**只用 Live 环境里确实存在、且实测解析得到的两族**：

```bash
fc-match "Noto Sans CJK SC"   # → NotoSansCJK-Regular.ttc: "Noto Sans CJK SC"
fc-match "Maple Mono NF CN"   # → MapleMono-NF-CN-Regular.ttf: "Maple Mono NF CN"
```

**必须显式指定字体族，不依赖 fontconfig 的 fallback** —— 实测宿主的
`sans-serif:lang=zh-cn` 落到 **wqy-zenhei**，与 Live 环境不是同一个结果。
依赖 fallback 就会「在开发机上好看、在 ISO 里变了样」。

**层级刻意少**（6 档）：大字 + 少层级 = 好读，这是「减少认知负担」在排版上的做法。

### 2.6 间距

8 px 基准，阶 `s1=8 / s2=16 / s3=24 / s4=32 / s5=48 / s6=64`；
页面左右内边距 `pagePadding=48`，卡片内边距 `cardPadding=24`，
内容最大宽度 `contentMaxWidth=880`（中文正文行宽 ≤ 32 全角字）。

### 2.7 动效

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `motionFast` | 140 ms | 悬停、按下、勾选 |
| `motionNormal` | 240 ms | 翻页、面板展开 |

**无循环动画**（只有加载态的不确定进度条例外 —— 它表达的就是「还在等」）。
软件渲染下动效降级，不依赖硬件合成。

**LOGO 只保留一次很短的淡入**（`motionNormal × 2`，收尾即定格）。

### 2.8 适配

主画布 **1280×800**；最小 **1024×600**；最大不设限（放大留白与字号，不拉伸控件）。
所有尺寸走相对单位，不写死像素宽。

**硬要求：每一页在 1280×800 上必须一屏放得下，不滚动。**
滚动是被尽量推迟的最后一招 —— 首屏让人滚动就已经输了。
实测（`measure` 脚本，见 §8）：

| 页面 | 内容高 | 可视高 | 需要滚动 |
|---|---|---|---|
| 欢迎 | 252 | 619 | 否 |
| 磁盘 | 244 | 508 | 否 |
| 账户 | 468 | 508 | 否 |
| 安装 | 481 | 514 | 否 |
| 完成 | 450 | 532 | 否 |

**1024×600 上欢迎页会略高于一屏**，这时才出现滚动条（`PageShell` 里那条 4px 的细条），
同时主视觉自动从 180 收到 128 —— 有意的降级，不装作放得下。

## 3. 减少认知负担：具体做到哪几条

| 手段 | 具体做法 |
|---|---|
| **默认路径只留一个真决策** | 认到**恰好一块可用盘**时自动选中（理由写在页面上），用户只需确认 —— 不是「在列表里找出正确的那块」 |
| **行话收进折叠区** | 面上只说 `系统分区 (512 MiB)`、`数据分区 (剩余)`；`ESP` / `GPT` / `vfat` / 对齐值放进「技术细节」展开区 |
| **一页一个主按钮** | 主行动永远只有一个实心按钮；返回是幽灵按钮 |
| **错误说人话 + 下一步** | 复用后端 `InstallerError.render()` 的第二行（「→ 接下来敲什么」），不自造一套文案 |
| **失败不自动重启安装器** | 与 [M0 验收口径](../../knowledge/05-测试方法.md) §5 一致：崩了不该在残骸上接着装 |
| **不显示不能用的开关** | 后端不支持的能力不画成可点控件（见 §5.2） |
| **进度不假装** | 装包阶段没有细粒度事件 → 「按阶段推进 + 已用时 + 真实滚动日志」，不编假百分比 |

**页面流（2026-09-25 评审定，已在 `qml/Main.qml` 里接线）：**

```
加载 → 欢迎 → 网络 → 系统磁盘 → 磁盘分区 → 确认擦除 → 账户 → 安装详情 → 安装 → 结束
                ↑                                                    ↑
        无论通不通都出现                          最后一颗实心按钮「开始安装」在这一屏

分支：欢迎「高级安装」→ 语言 / 键盘 / 时区 / 主机名（四项都有默认值，改的人自己进去）
```

三处与旧版不同，都是评审定的：

1. **语言 / 键盘 / 时区 / 主机名不在主流程里**，收进「高级安装」——它们都有能用的
   默认值（`zh_CN.UTF-8` / `us` / `Asia/Shanghai` / `mipl`），不改的人不该被拦四道。
2. **网络页永远出现**（原设计是「只在未联网时插入」）：直接跳过会留下不安，
   所以它固定占一屏，通了主按钮就是「继续」。
3. **「安装详情」放在账户之后、安装之前**：所有决定都做完、动盘之前核对一次；
   进度条因此照后端 `events.PHASES` 画六段（准备 / 磁盘 / 装包 / 配置 / 引导 / 完成），
   不再用旧版发明的「磁盘 · 账户 · 安装」三段。

**逐页规格以各页自己的文件头为准**（`installer/frontend/qml/pages/*.qml`）——
那里写的是「为什么这样画」与踩过的坑，比这一节更近。

## 4. 页面规格

> ⚠️ **下面 P0–P5 是「五页时代」的规格**，流程改成上面那样之后**部分已被替换**：
> 欢迎页不再含就绪检查与「即将安装」摘要（`WelcomePage.qml` 现在只有 LOGO + 产品名 +
> 一句定位语）；磁盘那屏拆成 选盘 / 分区 / 擦除确认 三页；账户页只留 用户名 / 密码 /
> 再次输入 / root 复选框；完成页只剩「装好了」+ 一行 + 重启。
> 保留这一节是因为**口径**（为什么这么设计）仍然有效，机制细节看代码与各页文件头。

### P0 · 加载态

居中 LOGO + `正在准备安装环境…` + 不确定态进度条。**窗口一显示就画**，不等任何后端调用。

**存在的唯一理由：** [Issue #53](https://github.com/MipLinux/MipLinux/issues/53) 实测
「从图形出现到窗口画出来要 10 秒以上（黑屏 + 鼠标先出现）」。那 10 秒不该是设计遗漏。
**根因不在本线** —— 本文只保证那 10 秒是**有意设计的状态**。

### P1 · 欢迎

| 区域 | 内容 |
|---|---|
| 主视觉 | LOGO 240px（透明底压浅色面）+ 字标 `MipLinux` + 一行定位语 |
| 情绪价值 | **来自版面与字体，不来自装饰**：左右两栏、大留白、一次淡入。LOGO 原样显示，外面不加环、不加星光、不做描线 |
| 就绪检查 | 网络（`nmcli`）/ 目标盘（认到 N 块）/ EFI（已检测），三行 |
| 即将安装（只读摘要） | `语言 zh_CN.UTF-8 · 键盘 us · 时区 Asia/Shanghai`，每行灰字标 `v0.1 默认值` |
| 主行动 | `开始安装`；右上角 `高级模式` |

**未就绪不置灰按钮** —— 置灰让人猜为什么；点了把问题说清。

### P2 · 选择磁盘 + 擦盘二次确认

- 盘列表一行一块：设备路径（等宽）、型号、容量（等宽）、状态胶囊。
- 状态胶囊优先级：`正在使用`（危险，禁用）> `太小`（危险，禁用）>
  `可移动设备`（警告）> `已有分区表`（警告）。
- 恰好一块可用盘 → **自动选中**，直接进确认态。
- 分区预览：`1 MiB 对齐 · 系统分区 512 MiB (vfat) · 数据分区 剩余 (ext4)`；技术细节折叠。
- **二次确认：逐字输入设备路径** —— 与 [cli.py](../../../installer/backend/mipl_installer/cli.py)
  第 167 行的守卫**同一套语义**。
- 固定一句：`盘上现有数据将全部丢失，且无法恢复。`

### P3 · 账户

| 字段 | 校验 | 显示 |
|---|---|---|
| 用户名 | 复用 [configure.validate_user](../../../installer/backend/mipl_installer/configure.py) 第 139 行的正则，逐字实时校验 | 行内 |
| 密码 / 确认密码 | 非空 / 一致 | 行内 |
| 主机名 | 非空合法 | 行内 |

**必须在界面上说的一句：** 不设 root 密码 = **root 保持锁定，只能用 sudo 提权**
（[configure.py](../../../installer/backend/mipl_installer/configure.py) 第 268 行的后端口径）。

**前端边界：** 用户名正则**调用**后端函数，不在前端重写一份 —— 重写就是
「包清单唯一来源」那条约定在验证逻辑上的翻版。

### P4 · 安装

阶段条 `磁盘 · 账户 · 安装` + **已用时** + 不确定态进度条 + 等宽滚动日志
（默认折叠，接 `Event.detail` 与 `Reporter.command()`）。
失败时红色面板给 错误原文 + `hint` + `重试` / `查看完整日志`。

**后端事件粒度：** `PHASES = ("start", "disk", "packages", "configure", "boot", "done")`
（[events.py](../../../installer/backend/mipl_installer/events.py) 第 15 行）—— **只到阶段，没有百分比**。
装包阶段最长，所以靠「已用时 + 真实滚动日志」传达「还活着」。

### P5 · 完成

汇总目标盘与账户；明确一句 `Live 介质可以拔掉，重启进入新系统。`；
主按钮 `立即重启` 调 `systemctl reboot`。
一行灰字：装后系统的中文与 NVIDIA 支持由 M3 落地。

### 4.1 边界状态（五页共用）

断网 · 零块盘 · 盘太小 · 盘在用 · 装包中途取消 · 窗口 1024×600 降级 ·
装包失败 · 引导失败。

## 5. 高级安装（原「高级模式」，2026-09-25 评审重定）

**内容就四项：语言 / 键盘 / 时区 / 主机名**（`AdvancedPage.qml`）。
它们都有能用的默认值，主流程里一个都不占屏；要改的人从欢迎页的「高级安装」进去。

**形态：** 一页**设置清单**（不是向导里的一步，也不是浮层）：四行，每行显示当前值，
点进去是那一页（列表 / 输入框），选完回到这一页，返回则回欢迎页。
改过的项在行首打一个**蓝色小点**（纯装饰）—— 一眼看出「我动过什么」，不必读字。

**旧的「高级模式面板」已作废**（`AdvancedPanel.qml` 已删）：它的四个分组里，
`分区` / `账户` / `主机名` 在主流程里已经有了更清楚的位置（分区页 / 账户页 / 主机名页），
剩下能摆的只有这四项。同理，旧的「安装计划」页（`PlanPage.qml`）也**作废删掉** ——
它的内容被 语言 / 键盘 / 时区 / 主机名 / 安装详情 五屏瓜分干净。

### 5.1 边界

- 高级安装里的四项**只改默认值**：不动它就是默认行为，主流程一屏都不多。
- 所有守卫**一个都不减少**：整盘擦除仍要逐字输入设备路径。

## 6. 接线所需的四件后端能力（**2026-09-26 已全部落地**）

G3 时这里写的是「本线不碰 `backend/**`，四件能力只写 issue」。2026-09-26 维护者
把接线所需的 backend 文件一并划给 G 线（**只此一轮**），所以它们不再是待办：

| # | 缺什么 | 落在哪 |
|---|---|---|
| 1 | 候选磁盘枚举 | `disk.list_candidates()` / `detect_disks()` / `inspect()`：sysfs 枚举（**一条盘要同时过「有 `device`」与「名字不是 sr/fd/loop/ram/zram/dm-/md」两道判据**），`blkid -p` 补文件系统类型与卷标（**不挂载**）。判据沿用 sysfs，**不许用 `lsblk` 的列表**（[M1 踩坑记录](../../archive/2026-09-22-安装器M1踩坑记录.md)） |
| 2 | 编排循环从 `cli.py` 抽出来 | `pipeline.py`：`Plan`（界面收集到的全部意图）+ `State` + 四个公开 `step_*` + `run()`。`cli.py` 与 `InstallController` 是同一个 `Plan` 的两个调用者 |
| 3 | `confirm()` / 密码可由前端注入 | `pipeline.run(confirm=…)` 是**必填参数**（没有默认实现，免得被人顺手用 `lambda: None` 抹掉）；密码走**参数**不走 stdin |
| 4 | 键盘与时区可调 | `TargetConfig.keymap` + `options.py` 的四个校验（见 §5.2） |

顺带补上的两件（本来不在表里，但「就绪检查」与「网络页」没有数据源）：

* `options.py` —— 语言 / 键盘 / 时区名单 + `validate_*`；`confined()` 挡住
  `../../etc/passwd` 这类**路径逃逸**（拼 `zoneinfo/<名字>` 之前必须先关住名字）；
* `network.py` —— `nmcli` 的读取与解析（`state` / `wifi_networks` / `connect`）。
  **密码走 stdin 的 `--ask`，不进 argv**（argv 会留在进程列表里）。
  ⚠️ **未实测**：QEMU 里没有无线网卡，`connect()` 那条路只有单测覆盖。

界面的接线方式与实测状态见 §8，桥接层的形状见
[bridge/README](../../../installer/frontend/bridge/README.md)。

### 8.1 否决过的写法（省得别人再试一遍）

| 写法 | 实测结果 |
|---|---|
| `qmlscene` / `qml` 跑 QML | 本机连纯 QML 都加载不了（`Library import requires a version`）—— Qt 工具链自身的问题，见 §1 |

| `strokeStyle: ShapePath.DashLine { … }` | 报 `Type 'ShapePath.DashLine' cannot declare new members` |
| `implicitWidth` / `implicitHeight` 赋值在 `Column` / `Row` 上 | 只读属性，报错。要定宽得把根换成 `Item` 再包一层 |
| 父容器用 `implicitWidth` 定宽 + 子项 `width: parent.width` | `QQuickItem::polish()` 循环刷屏。宽度必须有**单一来源**（`PageShell.pageWidth`） |

## 9. 开机耗时归因（2026-09-26 实机反馈「黑屏很久」）

**结论先说：和页面数量无关。** 我们的界面在客机里只要 **0.36 秒**；那 100 秒是环境开销。
量法见 [`tools/boot-probe.py`](../../../installer/frontend/tools/boot-probe.py)：一次开机同时拿
QEMU monitor 的**逐秒截图**与**客机 journal**（`--serial console` 给的是串口 root shell）。

### 9.1 时间线（QEMU 冷启动，从 QEMU 起进程算）

| 时刻 | 阶段 | 归谁 |
|---|---|---|
| 0–2s | OVMF 固件 | 引导链 |
| 2–19s | **引导菜单 + 12 秒倒计时** | profile |
| 19–42s | kernel + initramfs + squashfs 挂载（客机里 kernel 3.9s） | 引导链 |
| 42–70s | systemd 用户态：**time-wait-sync 25.3s**、**ldconfig 18.1s**、pacman-init 9.7s | profile / archiso |
| 客机 29.9s | `mipl-installer.service` 已经启动 | — |
| ~70–72s | cage 接管 DRM，屏幕转黑 | kiosk 链 |
| **107s** | 安装器第一帧上屏 | 见 9.3 |

### 9.2 客机内实测

```
PySide6 import                     0.57s      ← 不是它
fontconfig 第一次扫描（fc-list）   12.9–18.3s  ← 同一台机器第二次 0.07s
整套 QML 首帧（字体预热之后）       0.36s      ← 也不是它
```

fontconfig 那笔钱花在**从 squashfs 读字体元数据**（18 秒里 11–12 秒是 system 时间），
读完进页缓存就再也不花。界面第一帧要画中文，这笔钱正好压在「第一帧」上。

### 9.3 本线已经做的两件

- `mipl-kiosk` 在 cage 起来的同时**后台预热 `fc-list`**：把那 18s 挪出关键路径；
- `LoadingPage` **先出图后出字**：首帧只画 LOGO（不碰字体），下一帧才显示文字 ——
  万一预热没跑完，那 18s 也发生在「已经有画面」之后。

### 9.4 剩下的（**归 G 线，待处理**）
